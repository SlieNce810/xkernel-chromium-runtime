## 冻结项

在创建决赛候选 tag 前填写以下项目，并把每项的 SHA 或命令写入同一批 evidence：

| 类别 | 冻结内容 | 记录位置 |
|---|---|---|
| 内核 | 分支、commit、首个可运行版本 tag、决赛候选 tag、工作区状态 | `env.txt`、`manifest.txt` |
| 用户态 | rootfs、overlay、Chromium、Weston、测试页面 SHA-256 | `manifest.txt` |
| QEMU | 版本、AArch64、纯 TCG、4 vCPU、内存、virtio 设备参数 | `cmd.txt`、`platform-compliance.txt` |
| 页面 | `index.html`、`interaction.html`、`layout.html` 的 URL 和 SHA | 判据 JSON、`manifest.txt` |
| 测量 | 启动首帧、页面加载、renderer 创建、峰值内存的采样定义 | `metrics.csv`、报告 |
| 主机 | CPU、内存、操作系统、QEMU 路径和时间戳 | `env.txt` |

## 验收门槛

- `remote.sh check` 能以活动地址完成 SSH 只读检查；
- `active-address-audit.sh` 不再报告活动脚本或演示卡中的旧地址；
- 历史 evidence 中的旧地址保持原样；
- 决赛证据目录使用 `YYYY-MM-DD_<machine>-<scenario>` 命名，并保留 `console.log`、`cmd.txt`、`env.txt`、`manifest.txt`、`timestamps.csv`（适用时）；
- 性能 before/after 使用同一脚本、页面、QEMU 参数和采样规则，before 固定为首个可运行版本 tag。
