### 本次新获得的关键实测结论（都可复现，上游 main 分支）
1. **Alpine aarch64 的 `weston` 与 `chromium` 都在 `community` 仓库，不在 `main`**
   （查 Alpine CDN 目录索引得到）。默认 rootfs 通常只启 `main` →
   **官方 `xk-weston-start` 的 `apk add weston ...` 必然失败并 exit 1，图形起不来**。
   这是基础任务 40 分的头号阻塞点，修复方式已写入 S8 / guest-bootstrap.sh。
   实测版本：v3.21 `weston-14.0.0-r1`、`chromium-136.0.7103.113-r0`（101 MiB）。
2. **`make run` 的图形语义（读 `xtask/xkmake/src/qemu.rs`）**：
   - `GRAPHIC=y` → `-device virtio-gpu-pci -vga none -serial mon:stdio`；**不加则 `-nographic`**
   - `ACCEL=n` → 不加 `-accel`；无加速时固定 `-cpu cortex-a76 -machine virt,gic-version=3`
   - **`-serial mon:stdio` 是取证机制核心**：串口与 QEMU monitor 复用 stdio，
     `Ctrl-A c` 切换 → `screendump` → `Ctrl-A c` 切回。这是赛题唯一认可的截图方式。
   - 宿主架构 ≠ guest 架构时（x86_64 宿主跑 aarch64 guest）`hardware_accel()` 直接返回 None
     → **天然纯 TCG**，自动满足"初赛禁用 KVM/HVF"；WSL 被 `is_wsl()` 显式排除。
   - `make run` 会打印完整 QEMU 命令行；`XKMAKE_ARGS='--dry-run'` 只打印不执行。
3. **`drivers/Kconfig` 默认值**：`VIRTIO_BLK/NET/SOCKET/RNG` 默认 `y`、`VIRTIO_BUS_PCI` 是 choice 默认；
   但 **`VIRTIO_GPU`/`VIRTIO_INPUT` 无默认**，必须显式 `=y`（基线 defconfig 已给）。
   `NR_CPUS` 默认 4。
4. **rootfs 体积**：`alpine-busybox` 压缩仅 **9.5 MiB**，装 Chromium（101 MiB 包）必然 ENOSPC
   → **必须扩容 `truncate -s 4G` + `e2fsck -f` + `resize2fs`，且必须在 QEMU 关闭状态下做**。
5. **本机实况（env-check.sh 实测）**：
   - Windows 侧：无 QEMU、无 debugfs 原生实现 → **不能构建**
   - WSL2 Ubuntu 22.04.5：`make/gcc/curl/xz/python3/debugfs/resize2fs/e2fsck/dumpe2fs/truncate` **全部齐备**，
     **缺 QEMU（自带 6.2 < 要求的 8.0）、缺 rustc**；宿主 Ryzen 7 8845HS / 16 核 / 15 GiB
   - 结论：WSL 可作"试错开发环境"，**证据与性能数据仍应回原生 Linux 出**
     （OS 指纹不标准 + 额外虚拟化噪声 + QEMU 版本不达标）

### 踩到的坑（已修，写进物料避免复发）
- **`report | tee` 让 shell 函数跑在子 shell，累加的 `FAIL` 传不回父 shell，
  导致 `env-check.sh` 退出码恒为 0（静默失真）**。改为 `report > tmp` + `RC=$?` 再回显。
- **make 变量值含空格不要经 `XKMAKE_ARGS` 传**：`XKMAKE_ARGS=--disk-image a/b.img` 会被
  拆成两个 argv，后一个被 make 当成**构建目标**。改用 `DISK_IMG=...` 这个 make 变量。
- `pty`/`termios`/`os.statvfs` 是 Unix 专有 → `run-session.py` 改为惰性导入 +
  `require_unix_pty()` 友好提示 + `--dry-run` 可在 Windows 上校验参数。
- `report_user` 类小坑：PPM 转 PNG 用纯标准库手写编码器可避免 Pillow/ImageMagick 依赖（已验证 CRC 通过）。

### 踩坑实录（WSL2 特有 / 通用）
1. **国内无 QEMU 源码镜像**：TUNA/USTC/华为云都没有 → GitHub `git clone --depth 1 --branch v8.2.3 --recurse-submodules` 可行（GitHub 在该 WSL 可达）。
   release tarball 不含 meson 子模块，必须 git clone。roms/edk2 递归失败可容忍（deinit 掉）。
2. **WSL2 内核无 vhost-vsock**：xkmake 默认加 `-device vhost-vsock-pci` → QEMU 启动失败
   → **必须 `VSOCK=n`**（vsock 不在赛题设备组合里，关掉无损）。
3. **串口敲命令丢字符**（TCG 忙时 `sh /root/autorun.sh` 变 `sh/root/autorun.sh`）
   → 一切 guest 内操作改走 **autostart 注入**（debugfs 写 `/etc/profile.d/99-autostart.sh`），完全绕开串口输入。
4. **原始 99-autostart.sh 的 `start_foreground ... || return 1` 会短路 profile**：
   weston-start 失败 → 后续注入段全部不执行 → 注入段必须放**最前** + 移除原 weston-start 行。
5. **强杀 QEMU = 镜像损坏**：TaskStop/pkill 时 guest writeback 数据丢失，曾把 disk.img 打成
   busybox 读出 0 字节、仅 133MB 残留（应 308MB）→ **停机必须优雅（Ctrl-A x），debugfs 直改后必跑 `e2fsck -f -y`**。
6. **debugfs write 不能覆盖已存在文件**（`Ext2 file already exists`）→ 先 `rm` 再 `write`；
   且 **debugfs 不写 journal**，与未 checkpoint 的 journal 叠加会出孤儿目录（e2fsck 可修）。
7. **PowerShell 工具吞 wsl.exe stdout** → 所有 WSL 操作脚本内部 `exec > /mnt/e/.../xxx.log 2>&1` 落盘，Windows 侧用 Read 读。
   wsl.exe 宿主侧退出会带杀 WSL 内进程组 → **长会话必须 `setsid -f` 脱离**。
8. **status_check 的 sed 中文路径替换失败**（run4→run5 没生效，读到旧日志误判）→ 检查脚本路径硬编码。
