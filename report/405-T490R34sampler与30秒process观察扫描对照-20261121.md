# T490 R34 sampler 与30秒 process-observer 扫描对照（2026-11-21）

## 变更

统一 stability runner 新增 `STABILITY_PROCESS_SAMPLE_SECONDS`（默认5秒、最大60秒），并将解析值写入 dry-run、运行日志和 `stability-run-config.txt`。R34 取30秒，使 guest shell 的 process-tree 诊断扫描不再每5秒遍历 `/proc`；1 Hz 内存 sampler 与 memory window 不变。

T490 上 `bash -n`、`--help` 和无副作用 dry-run 均通过；dry-run 显示 `process_sample_seconds=30`、`memory_sample_seconds=900`、2 GiB pure TCG，`qemu_started=0`。真实 R34 首页 strict elapsed `589.302 s`，1/1重载和600秒保持通过。对照 R32（sampler-only、5秒 process scan）在1550秒 deadline strict timeout，R34 在相同 sampler/kernel/image/browser/page 参数下通过。这是一个单轮机制线索，支持 shell process 扫描负载有影响，但不是重复因果证明。

## 采样与稳定性结果

内存 bundle完整导出并通过串口/tar/gzip完整性校验，sampler仍 `FAIL`：274 sample IDs、215 missed、286 memory/tree 错误。sample-work 中位/P95为1.256/9.036秒，resident-walk中位/P95为172/1,256毫秒；因此RSS/PSS/USS峰值不接受。

30秒 guest family watch 配合相同 session 的调度偶有36秒间隔，normalizer按35秒 freshness gate拒收3个快照，故 R34 不构成稳定性总验收 PASS。下一轮应以25秒 family watch（保持 process scan 30秒）验证 liveness freshness，并继续优化 sampler 的1 Hz误差。
