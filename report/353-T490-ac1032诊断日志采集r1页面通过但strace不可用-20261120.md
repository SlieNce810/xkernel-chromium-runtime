# T490 `ac1032` Chromium 生命周期诊断 R1：页面和一次重载通过，strace 不可用（2026-11-20）

## 结论

在最终候选 kernel `ac1032fe98c382cc37646a12453b7141b789c9abfe1651ff5f8f1e0263767fa2`、2 GiB、AArch64 纯 TCG、Chromium 149.0.7827.53 下执行一轮 diagnostic-only 采集。页面首次 strict PASS 后完成 1/1 次真实重载，并保持 60.001 秒；事件归一化 159/159 通过。QMP 周期截图 11/11 成功，其中首个严格集全通过帧为 `shot-10-at0512s`，其后无失败帧，末帧通过。Weston 和 Chrome 的看门狗记录持续为 `yes`，最后一条位于 guest uptime 557 秒。

这轮没有产生 Chromium 周期诊断快照或 syscall 生命周期 trace：guest 的 `strace` 自检为 `STRACE_SELF_TEST=FAIL`，继而记录 `STRACE_SKIPPED=unavailable`；Chromium 诊断快照标记数为 0。Chromium 的串口日志仍记录 Browser PID 70、`MP_BROWSER_START_MONO_MS=39848`、本地首页的 `FileURLLoader::Start`，以及 Zygote/子进程相关日志，但这些信息不足以确定正式稳定性失败的卡点。

本轮使用了 tick 驱动的旧快照调度器（`autorun_mp_score_observe6.sh` SHA-256 `6cfd8b06244ab462c8e6762c772ae6c55d0879801950999459c58166088fb6f5`）。新的 guest 单调时钟调度版本已在提交 `cf4cae6` 中，但当时尚未同步到 T490，因此本轮不能验证该修改。下一轮会先核对并同步新脚本哈希，再重复同一诊断参数。

`STABILITY_DRIVER_RC=0`、`STABILITY_ROUND_RC=0`、事件归一化 `RC=0`，正式 gate 按 diagnostic-only 设计返回 `RC=78`。这是一次诊断通过，不是正式稳定性验收，也不改变统一审计的 `INCOMPLETE` 状态；本轮仅 1 次重载、60 秒保持，不能替代 10 次重载和至少 1,800 秒正式保持。
