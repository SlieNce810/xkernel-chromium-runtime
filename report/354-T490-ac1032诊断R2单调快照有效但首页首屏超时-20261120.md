# T490 `ac1032` Chromium trace 诊断 R2：单调时钟快照有效，首页首屏超时（2026-11-20）

## 结论

在最终候选 kernel `ac1032fe98c382cc37646a12453b7141b789c9abfe1651ff5f8f1e0263767fa2`、2 GiB、AArch64 纯 TCG、Chromium 149.0.7827.53 下，先将 `cf4cae6` 中的 guest 单调时钟快照版本同步到 T490，并核对脚本 SHA-256。五次 Chromium 诊断快照成功写入串口，分别在 Browser 相对时钟 `122.196`、`295.381`、`372.557`、`482.719`、`600.942` 秒触发。快照中的 Chrome 日志字节数依次为 23,054、34,247、34,247、35,282、35,282；`strace` 自检仍失败，`trace_bytes=0`。

这轮没有通过页面首屏。driver 在 700 秒 deadline 内完成 23 次 strict 轮询后超时，没有开始重载或保持阶段；QEMU 实际运行 712.6 秒。16/16 张周期截图都未满足官方首页 strict 判据，首个严格通过帧为 NONE，最终帧失败。timeout 帧 SHA-256 `197047b014d543072533cb1a4dc6d7909d288cfa358cae8ceb1f8ad3b43717aa`，与 shot-07 至 shot-16 的近白画面相同；shot-01 至 shot-06 使用另一浅色画面哈希 `2097d8f3…`，同样 strict 失败。事件归一化 225/225 通过，172 条 watchdog 记录中 Weston/Chrome 均为 `yes`，最后在 guest uptime 679 秒观察到约 571,232 KiB memfree；没有进程退出事件或 OOM 文本。

串口证明 Browser PID 70 启动，并请求了 `file:///usr/share/html-test/index.html`（`FileURLLoader::Start`）；日志没有 `DidCommitProvisionalLoad`、`RenderProcessHost` 或 `RendererMain` 相关记录。Browser/Zygote IPC 仍有活动，但不能证明 Renderer 完成文档提交或产生有效帧。该证据把阻断位置保留在“请求已发出、页面 strict/首帧未见”范围内，未证明某个 syscall 或 Wayland 错误是根因。

本轮有约 22,524 条内核 `futex` syscall 错误日志，主要为 `TimedOut` 与 `WouldBlock`，另有少量 `Interrupted`、`ERESTARTSYS` 和 `OperationNotSupported`。同一候选的诊断 R1 在页面和一次重载 strict 通过的情况下也出现了这些类别（总数约 8,091，运行时长与本轮不同）。因此当前对照不足以把这些日志直接判为页面阻断，也不能据此认定它们无害；仍需结合最小 futex 复现和具名调用点完成分类。D-Bus、GCM/SSL 网络日志亦没有与页面首帧失败建立因果关系。

`STABILITY_DRIVER_RC=1`、`STABILITY_ROUND_RC=0`、事件归一化 `RC=0`；正式 gate 按 diagnostic-only 设计返回 `RC=78`。这不是正式稳定性验收，候选正式 stability 状态仍为 FAIL，整体审计仍为 `INCOMPLETE`。
