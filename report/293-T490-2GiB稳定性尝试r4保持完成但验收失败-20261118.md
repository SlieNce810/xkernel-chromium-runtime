# T490 · 2 GiB 稳定性尝试 r4（2026-11-18，保持完成但验收失败）

## 结果

r4 从 strict 首页通过后保持了 1,805 秒，60 次 QEMU/guest liveness 采样均完成，Weston 和 Browser 始终报告存活；前五次真实 Ctrl+R 重载 strict PASS。第六次重载在 90 秒窗口内连续 16 次未通过页面判据，最终截图显示 Chromium 的页面无响应对话框。事件审查还发现五次 liveness 样本只有 Browser/BrowserChild 角色，没有新鲜完整的 Zygote 子进程/Renderer 拓扑。因此本轮稳定性验收失败。

## 失败证据与进程家族判定

重载 6 超时截图不是空白帧，而是 Chromium 的“Page Unresponsive”对话框，见 [第六次重载 PNG](../evidence/2026-11-18_t490-goal2g-stability-r4-review/load-06-reload-timeout.png)。驱动在失败后停止后续重载，但继续保持到 1,805 秒；因此有完整时长和 liveness 证据，不能把它算作十次有效加载。

运行时使用的旧规范化器报告 `repaired_liveness_count=4`、另有一条未修复。复核后发现它会用前一个完整快照覆盖更新的非空但不完整快照，这会把缺失的 Renderer 角色误当成仍存活。已收紧规范化规则：只忽略原始 `MP_FAMILY_COUNT` 计数标记；真实的不完整家族快照会使旧快照失效，任何非空部分快照都不能被覆盖。用该规则重放 r4 原始事件后，五条 liveness 记录被拒绝，事件 ID 为 `goal2g-stability-r4:149`、`:175`、`:183`、`:249`、`:256`；它们的角色只有 `browser` 与 `browser_child`。这表明相应时刻没有可复核的 Zygote 子进程/Renderer 证据，不推断为已经确认的内核进程退出。

严格事件重放后的 gate 复核报 `found 6 reload requests, expected 10`。runner 的正式 gate 因规范化器失败而未执行；原始结果码保持 FAIL。Watchdog 的 Weston/Browser 存活记录不能替代 Renderer 家族证据，也不能覆盖页面无响应。

## 下一轮定位

- 先定位 nav-06 页面无响应：关联 Chromium/renderer 日志、QMP reload 时间、Zygote 子进程候选 PID 与页面进程状态；保存发生超时的截图和完整事件序列。
- r5 的 host 命令设置了 `MP_FAMILY_DIAGNOSTICS=1`，但当时 `t490_round.sh` 没有把该值注入 guest，console 中没有 `MP_FAMILY_SKIP`。r6 的本地修订补上 `__MP_FAMILY_DIAGNOSTICS__` 占位符和 0/1 校验，并加回归断言；启动后先确认 guest console 实际出现 skip reason，再分析候选 PID 被排除的原因（进程目录缺失、starttime 不匹配、PPID 变化、Zygote 父进程不可见等）。
- 严格规范化器只修复由明确 `MP_FAMILY_COUNT` 标记造成的空家族记录；非空部分快照会使早期完整快照失效。runner 在规范化失败时也会写出 gate skipped 原因。
- 正式 gate 仅接受每次 liveness 当下的新鲜完整角色快照；部分角色快照和页面超时都继续记失败。
- 新一轮启动前同步严格规范化器到 T490、核验脚本 SHA-256，并运行测试；重复 1,805 秒保持和十次重载。

严格规范化器和解析器共 16 项测试通过；相关 shell 脚本 `bash -n`、Python `py_compile` 通过。
