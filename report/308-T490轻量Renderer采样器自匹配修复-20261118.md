# T490 轻量 Renderer PID 采样器自匹配修复

## 发现与结论

R5 冷启动日志里的 `MP_RENDERER_PIDS` 每个采样点都变成新 PID，但截图持续空白。追到 `autorun_mp_diag.sh` 的 light-mode 采样行后，发现 `ps | awk '/type=renderer/'` 会把包含该正则的 awk 命令行本身也匹配进来，因此这种 PID 变化不能证明真实 Renderer 进程重启，也不能单独解释 R5 的空白帧。

我将采样改成 `ps | grep '[t]ype=renderer' | awk '{ print $1 }'`。本机 Linux shell fixture 中，旧写法把一条真实 Renderer PID `70` 和观察器 PID `99` 都选中；修正写法只返回 `70`。`bash -n` 通过；更新后的 `autorun_mp_diag.sh` 已同步到 T490，SHA-256 为 `fc1b25e5f8cf143df33e17ac3317123e9c1881caf2637d753dc57c8c8efacf3d`。

这项修复只校正轻量 PID 观察值。它没有改变 R5 的事实：页面在 2,000 秒 ready timeout 后仍为空白，输入 driver 没有启动。下一轮需用修正后的观察器继续定位 Chromium 首帧启动阻断。
