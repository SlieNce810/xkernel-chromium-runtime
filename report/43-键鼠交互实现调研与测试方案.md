# 键盘、鼠标与页面交互实现调研

本阶段的目标是验证现有三页测试集的真实输入链路：键盘输入能够到达
`interaction.html` 的文本框，鼠标点击能够触发按钮，页面内的 JavaScript 与
CSS 布局检查能够完成，并且三页之间的跳转可复现。

## 采用的成熟方案

输入注入采用 QEMU 的公开机器接口，不在 guest 内重新实现输入协议：

1. QEMU QMP 的 `input-send-event` 支持 `key`、`rel` 和 `btn` 事件；键盘事件
   使用 qcode，鼠标使用相对轴事件和左键按下/释放事件。
2. QEMU HMP 文档同时公开了 `sendkey`、`mouse_move` 和 `mouse_button`，用于
   在 QMP 受限时做兼容性对照。
3. 现有平台参数已经显式加入 `virtio-keyboard-pci` 和 `virtio-mouse-pci`，因此
   注入后的路径是 QEMU virtio-input → guest evdev → libinput → Weston →
   Chromium Ozone Wayland。该路径与赛题的统一 QEMU 设备要求一致。

QEMU 官方参考：

- [QEMU Monitor](https://www.qemu.org/docs/master/system/monitor)
- [QEMU QMP Reference, `input-send-event`](https://www.qemu.org/docs/master/interop/qemu-qmp-ref.html#command-input-send-event)
- [QEMU Machine Protocol](https://www.qemu.org/docs/master/interop/qmp-spec.html)

页面端不新增自定义事件框架。当前页面已经使用浏览器标准能力：

- `interaction.html` 使用按钮的 `click` listener、文本框的 `input` listener，
  以及自检中的 Promise、定时器、DOM、JSON 和 `localStorage`；
- `layout.html` 使用 `load` listener、`getBoundingClientRect()` 和
  `getComputedStyle()` 检查 C1–C6；
- `index.html` 保持静态渲染验收页，交互验证集中在明确标注的交互页，避免改变
  初赛静态页的像素基线。

## 可复核测试顺序

1. 启动 `interaction.html`，用 QMP 键盘事件切换焦点并输入 `hello x-kernel`，
   检查回显文字；用 QMP 鼠标事件点击“真实点击 +1”，检查计数变为 1。
2. 用同一鼠标事件点击“运行自检”，等待 T4 定时器完成，检查核心结论为
   `6/6`，F1 文件系统附加检查为通过。
3. 通过页面链接进入 `layout.html`，等待 `load` 检查，滚动到结论条并检查
   C1–C6 为 `6/6`。
4. 返回入口页，确认三页文件都由镜像注入器逐字节读回，记录页面哈希、QEMU
   命令、输入事件脚本、截图和页面判据 JSON。

每个阶段的证据目录独立保存；截图和日志不覆盖以前的轮次。QMP 脚本只负责
发送事件和记录 QMP 返回值，是否成功由页面 DOM 状态、截图判据和 guest 日志
共同决定。

## 判定边界

- 不能只以页面加载或程序化 `button.click()` 作为真实鼠标通过；必须有 QMP
  键盘/鼠标事件记录和页面状态变化。
- `layout.html` 的 6/6 结论在页面较低位置，必须滚动或使用专门的 DOM/截图
  证据获取，首屏截图只作为布局几何证据。
- 若 QMP 事件返回错误，先记录 QMP 错误和 guest 输入设备状态，再查 QEMU
  官方接口或现有 libinput/Wayland 方案；不修改 Wayland 包或臆造内核输入语义。
