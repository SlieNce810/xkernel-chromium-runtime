# T490 冻结根独立冷启动复现与 freshness 通过 R39（2026-11-21）

## 运行条件

R39 使用 baseline freeze r3 的 `/home/mo/x-kernel` 和 `/home/mo/x-kernel/images/pkg-installed.img`：kernel SHA-256 `51c4028594e4aff9fc5b9964c4294a2904621c93e84093ac711858c454aed284`，rootfs SHA-256 `bab5c9f5dbf1e4a910bab569635bb9e44fe38c3b8cea94ae8eae4ce3f7a9fdb1`。Chromium为 Chrome/149.0.7827.53。平台为 2 GiB、AArch64纯TCG、SMP4、Cortex-A76、virtio GPU/keyboard/mouse，platform check 15/15通过；Browser argv含 `--js-flags=--jitless` 和 `--ipc-connection-timeout=600`。

为与R38同配置独立冷启动，memory sampler、lifecycle preload、guest clock sync关闭；process-tree scan 30秒，family watchdog 15秒；默认首页deadline 2400秒。runner参数为1次重载和420秒保持，diagnostic-only。

## 结果

首页 `official-index --strict` 于host `CLOCK_MONOTONIC` 466.289秒通过。240秒周期截图仍是全白；之后初始strict截图有效，SHA-256 `cd395836ae89ce969d0b8230b0793e5048359e118cacc0cf0cf1ac2eb258df98`。真实Ctrl+R重载为1/1 strict通过，420秒保持通过，完整QEMU会话889.3秒并正常退出。

事件normalizer处理256条事件，input/output均256，修复0、errors 0、parse errors 0。23个process-family snapshots中，14个host liveness检查的family age最大30.029秒，超过35秒的检查为0；因此R38观察到的freshness通过在R39再次复现。R39仍只证明此诊断配置下的一次冷启动、一次重载和420秒保持。

`STABILITY_DIAGNOSTIC_ONLY=1` 导致 `STABILITY_GATE_RC=78`，含义是正式10次重载/30分钟gate被跳过。guest clock sync、lifecycle preload和memory sampler关闭，所以466.289秒是host侧页面ready时间候选，不是四项性能正式样本；renderer-ready、first-frame、RSS/PSS/USS峰值均未取得。240秒白屏周期截图说明冷启动长尾仍存在，单凭一次strict通过不能覆盖该风险。
