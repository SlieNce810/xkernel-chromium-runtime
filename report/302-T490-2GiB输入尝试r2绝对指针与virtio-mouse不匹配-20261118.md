# T490 · 2 GiB 真实输入尝试 r2（绝对指针不受 virtio-mouse 支持）

## 结果

r2 使用已修复的 `qmp_input.py`，并在 guest uptime 约 529 秒通过第 46 次 `official-interaction` readiness 检查。输入开始后，QEMU 拒绝 `input-send-event` 的 `abs` 事件：`Input handler not found for event type abs`。平台命令实际挂载的是 `virtio-mouse-pci`，该设备提供相对指针；本轮没有成功发出文本、JavaScript 自检点击或页面导航。`input_rc=1`、`input_changed_pixels=0`、`round_rc=0`、`pass=0`。

## 根因与修复

R2 实际使用的 T490 `run_input_final.sh` SHA-256 是 `4b4ae102260a4de997448895bce9b9868928a75a54b95216a1acb1c917a56c09`。该版本默认启用 `ABS_POINTER=1`，因此把 QMP absolute mouse event 发给相对型 `virtio-mouse-pci`；T490 截图上的错误在 [qmp-input-error.log](../evidence/2026-11-18_t490-codex-2026-11-18_122759-input/qmp-input-error.log)，失败版 runner 快照保留在 [input review bundle](../evidence/2026-11-18_t490-codex-2026-11-18_122759-input-review/run_input_final.t490-r2.sh)。此前 4 GiB 通过证据记录的实际鼠标传输是 HMP `mouse_move`/`mouse_button`，键盘使用 QMP `send-key`，见 [report 284](284-默认多进程真实键鼠与决赛20分闭环-20261117.md)。

仓库 runner 已改为相对 virtio-mouse 默认走 HMP `mouse_move`/`mouse_button`，使用无钳制相对坐标；键盘继续走 QMP `send-key`。`run_javascript_round_mp.sh` 和统一验收 `input` stage 使用同一设置。修复版 T490 SHA-256：`run_input_final.sh` `d19be765a7d7c1ca3cb6d1850686c5d536777212e07384707200fdb1a934da5d`，`run_javascript_round_mp.sh` `a7925dffb1d49dac0a05af1502b1e91795dde85eddaff8fd559c1b19ee0908b8`，`qmp_input.py` `c2dcadb9c5c53fd856a4da1d64bc46e97fed56dd2a3e00b8d3075b37aea9a3b6`。T490 语法、help 与互斥参数拒绝预检通过；2 GiB 的真实 HMP 相对指针回归仍待下一轮，当前 Input 项保持未通过。

R1 的 `NameError: os is not defined` 已修复；本轮使用的 `qmp_input.py` SHA-256 为修复后版本 `c2dcadb9c5c53fd856a4da1d64bc46e97fed56dd2a3e00b8d3075b37aea9a3b6`。因此 R2 的绝对指针错误是修复前 runner 的独立阻断项。
