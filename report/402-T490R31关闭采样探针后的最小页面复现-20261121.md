# T490 R31 关闭采样探针后的最小页面复现（2026-11-21）

## 结果

R31 保持 R30 的 kernel、2 GiB AArch64 pure TCG、Chromium、Wayland、virtio 键鼠、默认多进程和 official index 判据；关闭 memory sampler、lifecycle preload 与 guest clock-sync，仅保留每30秒 process-family watchdog，诊断保持420秒。

指定页面首页 strict 通过，QMP 首次 ready elapsed 为 **496.649秒**，采样间隔30秒；1/1真实 Ctrl+R 重载通过，420秒保持结束时 Weston/Chrome 存活。strict screenshot 与 R30 的白屏 timeout 对照可见：R31 画面完整显示官方测试页。

## 解释边界

R30 在完整 memory sampler + lifecycle preload 条件下首页 strict 超时；R31 两者均关闭后页面通过。这说明观测负载可能影响这次失败，但两轮同时改变了 sampler、preload、guest clock-sync 和 watchdog 设置，**不能单独归因到某一项**。R31 没有同钟 Browser/renderer 事件与内存样本，不进入四指标性能报告。它只作为最小页面复现和R30失败的线索。

R31 证据含命令、环境、平台断言、QMP记录、完整截图和 SHA-256；原始 PPM 保留在 T490。见 [R31 evidence](../evidence/2026-11-21_t490-r31-minimal-page/) 与 [PPM哈希索引](../evidence/_ppm-sha256-r31-minimal-page.txt)。

## 下一步单变量隔离

R32 将保持 R31 设置并单独开启 memory sampler（900秒），关闭 lifecycle preload；保持段延长到480秒，为完整串口导出留余量。若仍 strict 通过，可进一步检查 preload 对页面路径的影响；若再次超时，优先检查 1 Hz 内存采样负载。无论结果如何，页面、进程、采样状态分别记账，不将 incomplete sample 纳入性能峰值。
