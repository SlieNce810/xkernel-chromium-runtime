# 赛题原文平台参数与 1.5G 资格线口径核对（2026-11-19）

## 核验范围

核对仓库原始赛题 PDF（6 页，PDF 1.7，SHA-256 `a394029e4eef75289811ceee615107b10c5ad66026b904c637c499dfb3c83696`），逐页渲染查看第六节评分标准和第七节统一平台及测量规范。

## 第七节平台要求

第七节(一)明确：

- 统一使用 AArch64 QEMU 虚拟平台，x-kernel kplat-aarch64 与组委会 qemu_defconfig 基线。
- QEMU 版本不低于 8.0；全部评分数据使用纯 TCG 软件模拟，KVM/HVF 等硬件加速数据不计分。
- 设备组合为 virtio-gpu-pci、virtio-input、virtio-blk、virtio-net。
- 功能证据使用 QEMU monitor `screendump`；主机录屏只作为演示辅助。

第七节没有规定 guest RAM 数值，也没有写明必须 `MEM=2g`。仓库正式复验选用 `scripts/t490/platform.env` 的默认 `PLAT_MEM=2g` 作为本项目统一 2 GiB 条件；4 GiB 功能闭环材料继续保留为不同的历史条件，不混入 2 GiB 结论。

第七节(二)要求性能数据由组委会统一脚本在同一主机测量，覆盖启动首帧、页面加载、renderer 创建延迟、峰值内存；每项至少重复 5 次，提交原始数据与波动范围；before/after 以首个可运行版本 tag 为基线。这与本任务的固定测量和五轮重复口径一致。

## 1.5G 资格线

第六节（二）的“性能与资源消耗”评分表列出资格线：现场完成指定页面加载且峰值内存不超过 1.5G；未通过资格线，该项计 0 分。第七节要求统一脚本测峰值内存，但原文没有进一步定义该 1.5G 数值究竟对应：

- guest 中 Chromium 进程树 RSS 之和；
- guest 总体内存使用；
- 还是 host 侧 QEMU 进程的 RSS。

因此不把 4 GiB guest 结果当作资格线判断，也不把 host QEMU RSS 冒充 guest Chromium RSS。正式数据同时保存 Chromium tree RSS/PSS/USS 与 host QEMU RSS 辅助值，并把 1.5G 资格线的统计边界标为“原文未定义、待明确”。
