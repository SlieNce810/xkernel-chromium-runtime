## 勘误 1 · r5 相邻帧心跳：不是「9 对均有变化」，而是「9 对全同（静态页预期）」

- **原表述**（report/40 §最终候选轮的结果）：「相邻截图心跳：9 对截图均有变化」。
- **归档证据**（`evidence/2026-10-02_t490-single-initial-r5/ppm-summary.txt`）：
  - `心跳成立对数 : 0`、`心跳=0/9`，9 对 `ppm-diff-shot-*.json` 的 `changed_pixels` 全部为 0；
  - `GATE strict_fail=0 probe_fail=0`——**门禁行不含心跳**。
- **定性**：`index.html` 是纯静态页（`scripts/testpage/README.md` 使用注意第 3 条：纯静态页两帧必然 0 差异，那不是 renderer 死）。因此 0/9 是**预期结果**，原报告的"9 对均有变化"与证据相反。
- **修正后表述**：「相邻 9 对帧完全一致——index 为纯静态页，属预期；renderer/JS 的存活证据看逐张严格像素判据（7/7×10）与 interaction/layout 轮结论条颜色，不以双帧差分判定。」
- **影响**：仅文档口径。功能结论（`SINGLE_GATE=1`、`strict_fail=0`、615 s 保持）不受影响。

## 勘误 2 · 判据组归类口径：统一用 ppm-summary 的严格集口径

- **问题**：同一判据在两处的组归类不一致——
  - layout：`layout_c3_box_model` 在 `*-assert.json` 里归 `viewport` 组，而 `ppm-summary.txt` 的严格集（5 项）把 viewport 组算入；
  - interaction：report/44 写「官方 interaction 严格集为 4/4」，实际 JSON 中 core 组 3 项（`official_banner` / `verdict_fail_absent` / `interaction_no_blocks`）+ viewport 组 1 项（`interaction_checks_table`），另 input 组 `interaction_selfcheck_pass` 通过；`info` 组 `interaction_awaiting_input=False` **不卡关**（默认未输入视图的正常描述）。
- **修正后口径**：对外一律以 `ppm-summary.txt` 的严格集行转述——interaction 记「core+viewport 4 项 + input 自检通过」，layout 记「严格集 5/5」；不逐字引用 JSON 的 group 字段。
- **影响**：仅转述口径，判据结果本身全部通过。

## 勘误 3 · layout 6/6 结论条：r21 本轮没有该证据，现有证据在 r19

- **原表述**（report/44 §通过证据）：引用 `layout-e2e.png` 说明「C1–C6 运行时检查结果为绿色 布局检查 6/6 全部通过……几何和结论分别取证是刻意的两张图」。
- **归档证据**：
  - `evidence/2026-10-02_t490-layout-e2e-r21/screenshots/layout-top.png` 与 `layout-verdict.png` **SHA-256 完全相同**（`c5330a1e…`），即滚动未发生；
  - `layout-verdict-assert.json` 中 `layout_verdict_pass=False`；r21 `ppm-summary.txt` 自带警告：「取景不够：['layout_verdict_pass'] 需要更高的画幅才可能入镜（当前 H=800）……必须用更高的窗口/滚动后重截」；
  - 报告引用的 6/6 图 `layout-e2e.png` 实际位于 **r19**（`2026-10-02_t490-interaction-single-e2e-r19/screenshots/`）。
- **定性**：几何 5/5 可宣称；**6/6 结论条证据缺位于 r21 同目录**，属证据缺口，不是渲染失败（结论条在整页 y≈1450，1280×800 首屏看不到，README 明示的取景陷阱）。
- **修正后表述**（report/44 已改）：「6/6 结论条证据来自 r19 轮（interaction 页跳转 layout?e2e=1 后滚动截图）；r21 自身的 `layout-verdict.png` 与 top 同哈希、`layout_verdict_pass=False`，本轮未产生滚动后结论条证据。」
- **待办**：按 report/45 §4-C3 补一轮 e2e 滚动 layout 轮，把 6/6 结论条落入同一目录后再对外引用；补齐前，材料中 6/6 必须注明证据在 r19。

## 勘误 4 · 缺口清单收敛为 8 条（原列 9 条超口径，且漏 virtio-input）

- **问题**：report/40 §兼容性缺口与补丁候选实际列了 9 条，超过评分口径「缺口 ×1/个（≤8）」；同时 report/44 定位的 **virtio-input 事件消费链未打通**（QMP 层 `query-mice`/`send-key` 成功，但内核 `EventDev::has_event → InputDevice::read_event` 无事件消费）未列入。
- **修正后清单**（8 条，report/40 已同步替换）：

| # | 缺口 | 来源 |
|---|---|---|
| 1 | fd 表下界 + zygote fd 继承语义 | report/39、40 |
| 2 | Unix 套接字 ancillary（SCM_RIGHTS/SCM_CREDENTIALS/MSG_CMSG_CLOEXEC）与 DGRAM/SEQPACKET 半关闭 | report/39、40（两条合一） |
| 3 | `ppoll_time64` 分派 | report/39 |
| 4 | procfs 字段（线程数/状态/内存/uptime 动态值） | report/39 |
| 5 | `PR_SET_PDEATHSIG` 最小 ABI | report/39 |
| 6 | TCP keepalive 选项（KEEPIDLE/INTVL/CNT） | report/39 |
| 7 | futex PI 未实现（EOPNOTSUPP 回退）+ RLIMIT_NOFILE 65536 vs fd 表 1024 | report/39、40（用户态配套，二合一） |
| 8 | **virtio-input 事件消费链未打通** | report/44 §末 |

- **影响**：条数回到 ≤8；补入的第 8 条正是"键鼠不可用"的直接答案，评委问到时有据可查。
