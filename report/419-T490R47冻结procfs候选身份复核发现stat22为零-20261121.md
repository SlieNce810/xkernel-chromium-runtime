# T490 R47 冻结快照 procfs smoke 暴露 stat field 22 缺陷（2026-11-21）

## 复核结果

R47 使用仓库当前 smoke runner 和 sampler 源码，文件已复制到 T490 的隔离 runner 目录并逐项核对 SHA-256。冻结快照加四个 procfs 驻留页补丁的候选内核 `kernel.bin` SHA-256 为 `ccf9f066…e6e4ada`，rootfs 是官方 `/home/mo/x-kernel/images/pkg-installed.img`（SHA-256 `bab5c9f5…f7a9fdb1`）。guest 条件为 AArch64、2 GiB、4 vCPU、Cortex-A76、pure TCG；平台断言 15/15。

内核的 `tree_smaps_rollup` 工作：guest sampler 记录 `samples=8`、`processes=2`、`missed=0`、来源 `procfs-tree-smaps_rollup`，并在 console 中输出完整 CSV 与 lifecycle events。更严格的 smoke 判据发现 root 和 child 的进程实例仍为 `5-0`、`11-0`，输出 `bad_start_times=2` 和 `PROC_TREE_SMOKE_FAIL output validation`。严格提取器拒绝本轮；原始行完整留在 [R47 console](../evidence/2026-11-21_t490-r47-procfs-tree-smoke-synced/console.log)，但没有生成有效的内存样本。

`PROC_TREE_SMOKE_BEGIN` 保存的 root `/proc/5/stat` 行在 comm 右括号后的 field 22（第 20 个 token）为 `0`。从原始 console 派生的 `memory-export/raw-identity-audit.txt` 确认 root stat 为 0，16 条 CSV 行的身份仅有 `5-0` 与 `11-0`，事件同样引用 `5-0`/`11-0`。Linux 要求该字段给出非零的进程启动 tick；T490 host Linux 对照及字段解释见 [report/383](383-T490-proc-stat-starttime与进程树内存单遍回归-20261120.md)。这说明 R46 的内核虽然补上 RSS/PSS/USS endpoint，但冻结快照仍缺少进程实例标识兼容性。

## 源码与修复

缺陷位置是 `task/ktask/src/task.rs` 的 task 构造和 `process/kprocess/src/stat.rs` 的 Linux stat 格式化。仓库已有 [`proc-stat-starttime.patch`](../patches/compat/proc-stat-starttime.patch)：为任务记录 guest monotonic 创建时刻，并将其按 `USER_HZ=100` 输出到 field 22。该补丁还增加格式化单元断言，检查 field 22 的位置和值。

R47 不计作兼容性修复已回归，也不计图形/浏览器功能、稳定性或性能样本。采集器 7 项回归全通过，其中包括对零 starttime 的拒收。QEMU 没有启动 Weston/Chromium，截图为 `Display output is not active.`、640×480，图形判据失败。

## 下一步回归

R48 将在冻结快照重建的独立 worktree 中按“`proc-stat-starttime.patch` → mapcount/resident-page → tree-rollup → dense count → direct-PTE”顺序应用补丁并构建。guest smoke 需同时验证 root/child `/proc/<pid>/stat` field 22 非零、`process_instance` 一致、完整 CSV/events 可通过提取器，以及 RSS/PSS/USS 均为正数。然后再评估同一 candidate 上的 Chromium sampler；shell smoke 通过仍不等于 Chromium 60 秒峰值窗口通过。
