# T490 R10 基线 120 秒间隔诊断：driver 通过、周期截图门禁失败（2026-11-19）

## 结论

以 R10 基线 kernel `51c4028594e4aff9fc5b9964c4294a2904621c93e84093ac711858c454aed284`、2 GiB AArch64 纯 TCG、相同 Chromium 149 rootfs、Weston/Wayland 与 QMP 120 秒重载间隔运行 diagnostic-only 对照。首页 strict 在 `402.192` 秒通过，8 次真实 Ctrl+R 导航的逐页 driver 判据均通过，包含第八次；driver 从首屏计时 `960.826` 秒后结束，QEMU 会话实际运行 `1364.8` 秒。

这不是完整稳定性 PASS。38 张独立周期 screendump 中，前 5 张是 strict 首帧前的 warmup；首个 strict 周期帧是 `shot-06-at0391s.ppm`。`shot-11-at0542s.ppm` 在一次已通过的导航后捕获到纯白画面，6 项核心判据失败；后续周期帧恢复，末帧通过。该帧 SHA-256 为 `197047b014d543072533cb1a4dc6d7909d288cfa358cae8ceb1f8ad3b43717aa`，与候选 120 秒诊断中从 `shot-15-at0663s.ppm` 到最终帧的纯白截图完全一致；基线仅在一张周期截图中出现此帧，候选轮则持续停留在同一帧。这是状态相同的证据，不能单独确定造成停留的原因。`ppm-summary.txt` 因这一张 post-pass 失败将其自身的 `round_assert` gate 判为 FAIL（`page_fail=1`、`post_pass_fail=1`），即使 nav-01 至 nav-08 的稳定性 driver 各自都拿到严格通过截图。

事件归一化也没有通过：432 个事件中，第 208 行的完整进程族快照年龄为 `35.041` 秒，超过归一化器的 35 秒界限 `0.041` 秒。远端结果为 `STABILITY_DRIVER_RC=0`、`STABILITY_ROUND_RC=0`、`STABILITY_NORMALIZER_RC=1`；正式 gate 按 diagnostic-only 设置跳过（`RC=78`）。311 条 Weston/Chrome 看门狗记录没有 `weston=no` 或 `chrome=no`；Browser/Zygote/Renderer 进程退出事件为 0，串口 OOM 行数为 0，末次记录 Weston 与 Chrome 仍存活、guest 可用内存约 262 MiB。

## 与候选轮的对照

同样 120 秒重载间隔下，R10 基线通过首屏并完成 8/8 个导航 driver 判据；最终候选 `ac1032fe…` 的上一轮诊断则在 1,803 秒内没有首屏 strict PASS，59 次首屏轮询失败，53 张周期截图均未通过（[report 349](349-T490-ac1032两分钟间隔诊断未到首屏-20261119.md)）。这说明 120 秒间隔本身不足以解释候选轮从启动开始持续白屏，候选 kernel 条件相关性值得继续核对。

两轮还共同暴露了周期截图流与逐页 strict driver 的差异：R10 基线在 nav-01 逐页判据通过后，周期截图仍有一张纯白帧。单次诊断不足以把候选归因为内核修复集或启动差异；正式候选稳定性轮此前仍在 nav-08 遇到 “Page Unresponsive”（[report 345](345-T490-ac1032稳定性轮第八次重载页面无响应-20261119.md)），本轮也不能推翻该失败。
