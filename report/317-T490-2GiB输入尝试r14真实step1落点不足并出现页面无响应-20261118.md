# T490 2 GiB 输入尝试 R14：真实 step1 运行，落点不足并出现页面无响应

## 结论

R14 使用与仓库 SHA-256 一致的 T490 runner，QMP ledger 确认实际执行 `pointer_mode="step1"`，不再是 R13 的 step4。交互页在第 46 次采样通过 ready；JS self-test 和动态键盘 echo gate 通过。计数仍为 0，CSS navigation 仍失败。

driver 在 step1 目标 `(281,674)` 后的截图显示光标约在 `(168,253)`，远离计数按钮；点击仍没有计数变化。导航尝试后出现 Chromium “Page Unresponsive” 对话框，final strict 页面仍未切到 layout。R14 ledger 记录 2,021 次 HMP 相对移动，远多于 step4 的 453 次。这个现象与大量细粒度输入造成的负担相符，但尚未建立因果关系；下一步改测 step3 中间步幅，同时缩短导航等待。

由于 `EVDEV_PROBE=0`，本轮没有 evdev event node 旁路事件记录；因此无法区分小步幅运动在 virtio-input、libinput 或 Weston 的具体缩放。Input 仍为 0/4，2 GiB 总分保持 16/20。

## 下一步候选

step1 50 ms 步幅比 step4 明显减小落点，仍不足以到达目标；2,021 个事件后出现页面无响应画面。下一轮测试 `INTERACTION_POINTER_MODE=step3`（3 像素、20 ms），使用页面坐标 `(281,674)` 和 `(350,710)`；CSS 导航等待缩短为 60 秒。此步幅仍是实验候选，不能视为已验证修复。
