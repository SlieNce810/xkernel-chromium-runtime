# T490 2 GiB 输入尝试 R10：探针开启时 ready 超时，QMP 早退成功

## 结论

R10 在默认 2 GiB、AArch64 纯 TCG、Chromium 149 默认多进程条件下，`EVDEV_PROBE=1`，ready gate 用尽 2,000 秒仍缺 `official_banner` 与 `interaction_checks_table`。188 张 readiness 判据及 26 张正式 QEMU screendump 均未通过 strict 页面判据；最终帧是灰白空画面。输入 driver 没有启动，所以本轮没有键鼠动作。

evdev sniffer 已启动并成功打开 `/dev/input/event0`（`QEMU Virtio Keyboard`）和 `/dev/input/event1`（`QEMU Virtio Mouse`）；串口没有 `EVDEV ev` 行。这个结果只证明 event 节点能打开，不能证明本轮事件消费路径正常或失败，因为 ready gate 失败后没有输入事件可观察。

本轮新增的 ready-timeout QMP 早退逻辑生效：`QMP_TIMEOUT_QUIT_RC=0`，QEMU 在 manifest 记录的 2,013 秒结束，较 2,400 秒计划少运行约 387 秒。`run_input_final.sh` 返回 2，原因是页面未达到 ready；证据没有被空白帧覆盖成 PASS。

probe-on 的 R8 与 R10 都在 ready gate 超时；no-probe 的 R7 和 R9 通过，R5 也曾在 no-probe 条件下超时。两次 probe-on 超时提示 observer 可能增加启动负担，但 R5 反例和整体轮次波动不足以建立因果关系。R10 是诊断失败轮，不作为性能样本或输入链结论。
