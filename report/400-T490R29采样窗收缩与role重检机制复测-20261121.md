# T490 R29 采样窗收缩与 role 重检机制复测（2026-11-21）

## 结果

R29 使用 R27 kernel `95db6f57…de34db` 和 R28 的 sampler role 重检5秒版本。内存采样维持1 Hz，请求850秒窗口；页面 strict、1/1真实重载与420秒诊断保持通过。Browser main-loop 与导航的探针事件已导出；`renderer_ready`、`first_valid_frame` 仍缺。

串口内存包完整到达，128块及tar/gzip哈希通过。sampler 状态仍为 `FAIL`：225个sample ID、205 missed、1,420行、268个内存/树错误。RSS/PSS/USS峰值无效，performance collector 因缺 first-frame 事件拒收整轮。

## R27/R29 机制方向对照

| 指标 | R27：1秒 role重检 | R29：5秒 role重检 | 单轮变化 |
|---|---:|---:|---:|
| sample IDs / missed | 225 / 210 | 225 / 205 | missed少5 |
| memory/tree errors | 277 | 268 | 少9 |
| sample-work 中位 / P95 | 1.357 / 8.977 s | 1.292 / 6.956 s | -4.77% / -22.51% |
| resident-walk 中位 / P95 | 185.688 / 1,399.518 ms | 186.021 / 1,092.314 ms | +0.18% / -21.95% |
| tree snapshot 总耗时中位 / P95 | 208.269 / 1,471.916 ms | 204.030 / 1,173.919 ms | -2.04% / -20.25% |
| overrun 中位 / P95 / 最大 | 2.046 / 15.873 / 59.825 s | 2.281 / 14.751 / 45.444 s | 中位略差、尾部略好 |
| sampler status | `FAIL` | `FAIL` | 无效峰值 |

两边各只有一轮；R27请求900秒、R29请求850秒，采样时段不同。R29 页 strict 588.909秒，R27 651.129秒，也不能据此归因到 sampler 角色重检频率。该候选改善了部分中位/P95诊断计时，但错误分类和尾部分布仍混合，且都没有有效内存峰值；**不计为可靠性能收益**。比较原始数据见 [`mechanism-comparison-r27-r29.json`](../evidence/2026-11-21_t490-r29-role-recheck-export/mechanism-comparison-r27-r29.json)。
