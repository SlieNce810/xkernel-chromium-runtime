# T490 · 2 GiB 稳定性尝试 r6（2026-11-18，重载与保持通过、Renderer 家族复核失败）

## 结果

r6 完成 strict 首页、1,805 秒保持和 10/10 次真实重载；第六次重载没有重现 r4 的页面无响应。driver 报告 PASS，但严格规范化器在 hold 窗口内拒绝五条家族 liveness，离线 gate 在第二条 liveness 样本停止。因此正式稳定性结论仍是 FAIL，不能把 driver 自测 PASS 当成稳定性 PASS。

## 家族快照来源冲突

hold-window 严格规范化器报告五条不完整家族 liveness，event ID 为 `goal2g-stability-r6:121`、`:175`、`:183`、`:259`、`:507`。这些 liveness 记录只有 `browser`、`browser_child`，没有 `zygote_child`。离线 gate 复核在 sample 2 报 `guest Browser/Zygote/Renderer process family missing`。

console 同时出现完整的 `MP_FAMILY` n=5/6 快照和不完整的 n=3/n=1 快照。observer 源码有三个写入同名 `MP_FAMILY` 的路径，driver 因而把不同来源的结果当成同一条家族观察；即使候选检查型 watchdog 在附近输出了完整快照，旧的部分快照仍可能覆盖 driver 的 latest family。这是观察来源冲突的强证据；当前不能据此确认 Renderer 实际退出。

诊断开关排除了 PID 472：该 PID 在开始时间读取前已消失，`start_ms=0`；同一 console 随后记录 `SANDBOX_EXIT pid=472 parent=177 exit_code=0`。family watchdog 同时记录到其他 Zygote 子进程候选。该短命候选没有解释五条缺失 `zygote_child` liveness 的原因。

## r7 修正

- watchdog 家族快照改用独立的 `MP_FAMILY_WATCHDOG` 标记；stability driver 只解析该来源，忽略主扫描器的 `MP_FAMILY` 与 `MP_FAMILY_COUNT`。
- r5 的 host 环境变量未传到 guest；r6 已通过 `t490_round.sh` 校验并替换 `__MP_FAMILY_DIAGNOSTICS__`，guest console 明确打印 `MP_FAMILY_DIAGNOSTICS=1`，并记录 66 条 skip reason。r6 的标记确认注入修复生效。
- 严格规范化器只在 hold 区间检查 liveness，不再把真实部分快照替换成旧记录。
- 这些代码和测试已在本地通过 18 项单元测试、`bash -n` 与 `py_compile`；下一轮会在 T490 重验脚本 SHA-256，并确认 `MP_FAMILY_WATCHDOG` 与 skip 原因日志都出现在 console。
