## 关键时间点

- 首页在第 21 次 readiness 检查通过，约对应纯 TCG 会话的 12–13 分钟；
- 第一次 `Ctrl+Tab` 后，布局页在第 3 次检查通过；
- 第二次 `Ctrl+Tab` 后，首页在第 2 次检查通过；
- `tabs-events.jsonl` 记录 `first_ready=true`、`second_ready=true`、`third_ready=true` 和
  `switches=2`。

页签驱动先等待页面严格像素通过，再发送按键。这样启动白屏不会被当成页签内容，也不会把
“页面还没有 renderer frame”误判为 Ctrl+Tab 失效。

## 运行条件

- Chromium 149.0.7827.53，镜像 SHA-256：
  `d7d89bcb466c1d9a7ab209220c8ab997f66c02b77c5e80d3ea10ed64c772a641`；
- 默认 Browser → Zygote → Renderer 多进程路径；
- `--ipc-connection-timeout=600`；
- guest 4 GiB、Wayland + Pixman + SwiftShader、纯 TCG；
- 输入路径为 QMP → virtio-input → evdev/libinput/Weston → Chromium。

本轮外层页签编排器在收尾前被一次脚本文件覆盖竞态打断，QEMU 子轮本身已完成并产出完整
`ppm-summary.txt`。`finalize_tabs_gate.py` 只接受该不可变 summary 的 `page_fail=0`、
`post_pass_fail=0`、`last_pass=1`，再重新运行三张截图的像素判据；gate 中明确记录
`round_rc_source=ppm-summary.txt (completed t490 round)`，没有修改原始 PPM 或 console。

## 对决赛分值的意义

这轮已经证明“同一个多进程 Browser 的至少两个真实 tab 可以切换并回到原页”。它不依赖
CDP、页面注入或单进程模式。接下来可在同一套 IPC600 基线下继续跑 interaction 页的真实
键盘/鼠标、JavaScript 自检和 CSS 布局判据。
