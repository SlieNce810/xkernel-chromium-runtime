# T490 冻结快照 procfs 进程树驻留页候选 smoke R46（2026-11-21）

## 结果

R46 从 baseline freeze r3 的 `b73e581` commit 和已归档 tracked diff 重建隔离 worktree，依次应用 `procfs-smaps-rollup-mapcount.patch`、`procfs-tree-rollup.patch`、`procfs-pfn-count-dense.patch` 和 `t490-procfs-resident-walk-direct-pte-r27.patch`。官方 `/home/mo/x-kernel` 没有被修改。冻结 tracked diff SHA-256 为 `b3a4d5ed…c0dea7`，与冻结材料匹配；build config SHA-256 为 `42e8d164…e33f669`。

`make build GRAPHIC=y ACCEL=n MEM=2g SMP=4 VSOCK=n` 成功，release 编译耗时 2m28s。ELF SHA-256 为 `8209d800…69b3054`，实际 QEMU kernel.bin SHA-256 为 `ccf9f066…e6e4ada`。guest 为 AArch64、2 GiB、4 vCPU、Cortex-A76、QEMU 10.2.1 pure TCG，平台断言 15/15。输入 rootfs SHA-256 为 `bab5c9f5…f7a9fdb1`；注入后的本轮磁盘 SHA-256 为 `c9197a8f…c683265`。

guest 自报：

```text
PROC_TREE_SAMPLER_RESULT run_id=proc-tree-smoke-01 samples=8 processes=2 missed=0 duration_ms=7026
PROC_TREE_SMOKE run_id=proc-tree-smoke-01 sample_rows=16 processes_started=2 memory_errors=0 bad_values=0
PROC_TREE_SMOKE_PASS
```

这表明补丁内核能从进程树 endpoint 为两个 shell 进程产生正 RSS/PSS/USS 值，短测没有 missed。但 T490 runner 使用的 autorun 与 C sampler 文件比仓库当前版本旧，串口没有输出完整内存 CSV 和 lifecycle events 标记。仓库提取器拒绝该轮，不能从这份日志复核逐行数值；提取器回归测试 7/7 通过。差异和拒绝原因见 [R46 evidence](../evidence/2026-11-21_t490-r46-procfs-tree-smoke/)。

本轮没有启动 Weston/Chromium。QEMU 显示 `Display output is not active.`，PPM 是 640×480，严格的图形截图尺寸判据失败。因此它只算 procfs shell smoke，不计图形会话、浏览器功能、稳定性或性能指标通过。

## 修复和后续验证

R45 的冻结内核没有 `smaps_rollup`/`tree_smaps_rollup` 与驻留帧枚举，因此 Chromium memory sampler 退化到不可用的逐 PID 路径。R46 从冻结状态集成对应补丁并验证接口可运行。R46 的完整原始 CSV 归档因 runner 版本漂移失败；后续 smoke 将从仓库版脚本生成独立 runner 输入副本，核对每个输入 SHA-256 后再运行，不放宽提取器。

R46 没有证明真实 Chromium 树的 1 Hz 采样、加载后 60 秒窗口、内存峰值、renderer-ready、首帧或性能收益。候选补丁还需与功能/稳定性回归联测；R44 的正式稳定性 PASS 仍只适用于未打 procfs 补丁的冻结 kernel SHA。
