## 结论

最终候选 kernel `ac1032fe98c382cc37646a12453b7141b789c9abfe1651ff5f8f1e0263767fa2` 在正式 2 GiB、AArch64 纯 TCG、Chromium 149.0.7827.53 参数下通过初始首页 strict；首屏在 driver 启动后 371.401 秒通过。随后 nav-01 的真实 QMP `Ctrl+R` 重载通过；nav-02 在90秒重载窗口内16次 strict 采样均失败，最后保存 timeout 帧并停止发出后续重载。driver 仍完成从 `page_ready` 起的 1,805.002 秒保持，最终为1/10重载；正式 gate 返回 FAIL。

周期 QMP screendump 65/65 成功。`ppm-summary` 记录4张首个 strict 周期帧前的 warmup、65帧中59帧 strict 失败，其中55帧在第一个通过帧之后失败；首个周期 strict PASS 为 `shot-05-at0360s`。最后周期帧在自动判据中又得到 strict PASS，但可视预览仍有 Chromium “Page Unresponsive” 模态框，因此不把它解释为页面已恢复。nav-02 的单独 timeout 预览同样显示该模态框；正式稳定性仍由超时与后续失败帧判定为 FAIL。

## 故障边界

首屏和第一次重载均可严格通过，第二次真实重载后出现 `Page Unresponsive`。该序列不同于两次正式候选失败中的“第八次重载卡死”及“首屏2,400秒 timeout”，说明候选存在重载次数和冷启动结果不一致的间歇性页面阻断。周期截图最后一帧虽然被严格像素判据接受，但画面仍叠有无响应对话框；这说明当前页面像素判据可能对该 modal 不够敏感，需要把 dialog OCR/模板判据作为 stability gate 的防假阳性补证。当前报告不把该候选判为稳定。

本轮只记录页面、导航和存活结果，没有启动可计入的四项性能采集；无性能收益结论。兼容性摘要仍依赖独立探针矩阵，不能由本轮重载结果替代。
