# T490 R28 sampler 角色重检降频与串口截断记录（2026-11-21）

## 变更

R28 延续 R27 kernel `95db6f57…de34db`，只改变 `proc_tree_sampler.c` 对已有进程的角色探测频率：进程树内存仍每秒采样；为判断既有子进程是否从 `child` 转成 Browser/Renderer/Zygote 等角色，`/proc/<pid>/task/<pid>/comm` 重检最多每5秒一次。AArch64 static musl 编译使用 `-Wall -Wextra -Werror` 通过。

## 运行结果

官方首页 strict 首次通过，`ready_elapsed_ms=557289.040243`；1/1真实重载通过，420秒诊断保持完成。此首屏时间比 R27 的651.129秒快，但只有单轮，且 R28 内存导出不完整，不能归因于角色重检降频。

本轮请求900秒、1 Hz sampler。保持段结束时 guest 已输出 memory export begin（预期151块、tar 332,288字节、gzip 28,854字节），但串口只收到145块且没有 `MP_PERF_MEMORY_EXPORT_END`。仓库 extractor 按协议拒绝不完整bundle；没有可读取的 `memory-export`、RSS/PSS/USS峰值或有效 sample-work 分位数。该轮因此不参与任何正式性能统计。

## 下一轮设置

R27/R28 的页面通过时间从651秒变为557秒，使900秒采样窗口的串口压缩/传输收尾紧贴420秒保持终点。R29 将采样时长设为850秒，仍从 Browser 启动附近覆盖strict页面后约335秒（超过所需60秒），在相同420秒保持下留出更多导出余量。页面时间或导出窗口不符时继续拒收，不会把 begin 行当成完整样本。
