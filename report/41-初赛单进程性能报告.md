# 赛题六初赛性能测量报告：单进程 Chromium

本报告只描述单进程主流程的测量。它用于初赛“提供可复现测量脚本和方法文档”的要求，不把单进程结果解释成多进程 renderer 性能结果。

## 固定环境

| 项目 | 值 |
|---|---|
| 分支 | `codex/initial-round-single-process` |
| 主机 | `mo-ThinkPad-T490`，Ubuntu 26.04，x86_64 |
| Guest | AArch64 x-kernel + QEMU 10.2.1，纯 TCG，2 GiB，4 vCPU |
| Kernel SHA-256 | `dcb862c9e83d1f019d712a773d3c848eb0d36cbfdf531d2cf3971b686229d2af` |
| 基础镜像 SHA-256 | `bb25e0b298d619a62df06b0ab044750c0885adc2d34602eb0c5875a022aaee09` |
| Overlay SHA-256 | `56dba17c74ff80399d32a3fceef9ffa724a0197992fdc5934e0e254a8d8cf4b2` |
| Chromium | `142.0.7444.59 Alpine Linux` |
| 页面 | `file:///usr/share/html-test/index.html` |
| 运行模式 | `--single-process --no-zygote --in-process-gpu` |

每次测量都是新 QEMU、新工作镜像和新 Chromium profile。证据目录不覆盖旧轮次。

## Host profiling 与工具边界

profiling 证据：[2026-10-02_profile-single](../evidence/2026-10-02_profile-single/)。使用同一单进程启动参数和相同 overlay，host `/proc/<qemu_pid>/{stat,status}` observer 连续采样约 303 秒：

| 指标 | 值 | 观测边界 |
|---|---:|---|
| QEMU CPU 时间增量 | 526.1 s | host `/proc/<pid>/stat` 的 user+system ticks |
| 单核尺度平均 CPU | 173.56% | QEMU 进程 CPU 时间 / 墙钟时间；不是 guest CPU 利用率 |
| QEMU 峰值 RSS | 1,671,512 kB | host QEMU 进程 RSS，包含虚拟机运行时开销 |
| minor fault 增量 | 52,122 | host QEMU 进程 |
| major fault 增量 | 0 | host QEMU 进程 |
| voluntary context switch 增量 | 294,742 | host QEMU 进程 |
| nonvoluntary context switch 增量 | 31 | host QEMU 进程 |

observer 源码为 [scripts/observe_qemu.py](../scripts/observe_qemu.py)，输出为 `qemu-proc.csv` 和 `qemu-proc.json`。

`perf stat`/`perf record` 和 eBPF 已实际尝试，但 T490 主机权限限制导致它们不能产生有效样本：

- `perf_event_paranoid=4`，普通用户无 CPU event、kernel profiling 或 tracepoint 权限；`perf.data` 大小为 0；
- `bpftrace` 无法读取 `/sys/kernel/tracing/available_events`，返回 `Permission denied`；
- guest `strace` 仍受 x-kernel `ptrace` 未实现限制，不能作为正式 syscall 延迟数据。

原始失败输出保存在 profiling 目录的 `perf-stat.stderr`、`perf-record.stderr`、`bpftrace.log` 和 `flamegraph-status.txt`。这部分作为工具能力缺口提交，不能冒充 perf/eBPF 火焰图结果。若评测主机提供 CAP_PERFMON、BPF 权限和 FlameGraph 工具，再用同一 `profile-command.txt` 重跑即可。

## 功能基线关联

五次性能批次使用的功能门禁与最终单进程候选保持一致。最终 10 分钟候选证据为 [2026-10-02_t490-single-initial-r5](../evidence/2026-10-02_t490-single-initial-r5/)，其中官方 index 严格像素 `strict_fail=0`、`SINGLE_GATE=1`。性能批次本身使用 120 秒单进程保持窗口，不能替代最终 600 秒功能候选；它只用于初赛测量方法、重复次数、中位数和波动范围。
