### 4.4 ⚠️ udev 次设备号陷阱（v2 新增）

`guest-bootstrap.sh` 通过伪造 `/run/udev/data/c13:{1,2}` 骗过 libinput：

```
/run/udev/data/c13:1  → ID_INPUT_MOUSE=1      # 脚本假定 1 = 鼠标
/run/udev/data/c13:2  → ID_INPUT_KEYBOARD=1   # 脚本假定 2 = 键盘
```

但**次设备号由 guest 内 evdev 枚举顺序决定**，而 `QEMU_ARGS` 里键盘在前、鼠标在后。
**每个新设备组合都必须实测核对**：

```bash
# guest 内

cat /proc/bus/input/devices          # 看 Handlers 与 Name（x-kernel 若未实现则该文件不可用）
```

写反的后果是**静默无输入**（不报错、桌面正常），直接丢决赛「键鼠回显」4 分。
核对结果写入 `metadata.json.devices` 后再固定脚本。

## 5. 阶段 2：图形链路（**G4 优先**，重排）

### 5.1 ★ G4：wayland `SCM_RIGHTS` fd 跨进程传递（唯一硬阻塞）

**现象**（v16 实测，weston 起来后 6 秒内退出）：

```
libwayland: file descriptor expected, object (10), message create_pool(nhi)
Error: /usr/libexec/weston-desktop-shell apparently cannot run at all.
Quitting...
```

**为什么是硬阻塞**：`wl_shm.create_pool` 必须通过 unix socket 传 fd；compositor 与客户端是两个进程。
`SCM_RIGHTS` 不通 → 所有 wayland 图形客户端（desktop-shell、Chromium）都无法建缓冲。

**步骤 2.1.1：独立 C 探针（先判定，再修）**

复用 `drmprobe.c` 的编译/注入流程（宿主交叉编译 + debugfs 注入，不经 apk solver）：

| 子项 | 要求 |
|---|---|
| 传 | 父进程 `sendmsg()` + `SCM_RIGHTS` 送一个 fd |
| 收 | 子进程 `recvmsg()` 取 fd，记录 `msg_controllen` / fd 个数 |
| 用 | 对收到的 fd 实际 `read`/`write`（不能只看「收到了」） |
| 记 | 每一步 `errno`、fd 编号、生命周期（发送后关闭原 fd，验证引用计数） |
| 反例 | 对照一组**不传 fd** 的 `sendmsg()`，确认普通数据通路本身是好的 |

**步骤 2.1.2：定位**

- 首选嫌疑：`posix/net/src/cmsg.rs` 的 `SCM_RIGHTS` 收发实现（`ancillary data` 长度/对齐/
  `msg_controllen` 回填是否正确）。
- 次选：`sendmsg`/`recvmsg` 的 `iovec` 与 `cmsghdr` 对齐（`CMSG_ALIGN`）；
  `SCM_MAX_FD` 上限；`MSG_CMSG_CLOEXEC` 处理。
- 若探针**通过** → 说明 fd 通路本身没问题，转 5.2（运行库/依赖）而不是继续改 cmsg。

**验收**

- ✅ 探针全绿（含"收到的 fd 真的可读写"）；
- ✅ weston 日志无 `file descriptor expected` / `error in client communication` /
  `apparently cannot run at all`；
- ✅ weston 存活 ≥ 600 s（进入 §9）。

### 5.2 weston 运行库完整性

console 有 `Fontconfig error: Cannot load config file /etc/fonts/fonts.conf` 告警。
补齐并冻结：`/etc/fonts/fonts.conf` + 字体、`seatd`、weston DRM/Xwayland/客户端包、
Chromium 及其软件渲染依赖。

**安装路径固定为宿主跨架构预装**（**不要**在 guest 内跑 `apk add`）：

```bash

apk-tools-static --usermode --arch aarch64 --root <imgdir> add --no-cache <pkg>...
```

包清单、版本、镜像 sha256 全部写入证据。

### 5.3 原生 VT / seatd 路径（P2，可延后）

补齐 `/dev/tty0`（4:0）语义、控制终端查询、procfs `tty_nr` 字段、VT 打开/激活 ioctl。

**优先级说明（v2 明确）**：G1（udev/sysfs）与 G2（VT）**目前均已被用户态手段绕过**，
原生路径是「合规性更漂亮 + 更能写进 25 分缺口与补丁」的加分项，**不是**打通 40 分的必经之路。
**G4 打通优先于本节**。

**证据标记规则（不变）**：最终验收链路上的会话必须走**原生 Weston**；
凡使用 `LD_PRELOAD=libseat-shim.so` 或伪造 sysfs 的会话，
在 `metadata.json.status` 中标记 **`diagnostic-only`**，不得计入 40 分证据。

### 5.4 sysfs 正式形态（从"必做"降为"加固项"）

现状：`memfs::SYSFS_TYPE` 已是"内核填充的树"（源码注释明示 *the directory tree is owned by this
superblock*）。**推荐正式形态是在挂载期或设备注册回调中由内核填充** `/sys/class/drm/*` 与
`/sys/dev/char/*` 节点，而非新增独立 fs crate；用户态伪造仅作过渡与验证手段。

**不做强制**：`drmGetDevices2()` 返回 `0` 已证非阻塞，**从验收矩阵中移除**。

## 13. 默认假设

- 评分主机固定为 **T490 原生 Linux**；Windows / WSL2 只做编辑、同步、结果查看。
