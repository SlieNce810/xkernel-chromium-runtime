# T490 2 GiB 无 startup-trace 内存采样控制 R16（2026-11-20）

## 结论

R16 用与 R15 相同的内核、2 GiB guest、指定首页、Browser 默认多进程、内存 sampler、guest clock sync、14 秒 family watchdog、1 次真实重载计划和 800 秒 diagnostic hold，唯一目标是关闭 Chromium startup trace 后观察进程树采样；`--trace-startup` 及 trace 文件输出均未启用。

首页在 700 秒 `STABILITY_READY_TIMEOUT` 内没有 strict 通过，driver 在第 23 次页面轮询后发送 QMP quit，截图为全白。结果 `STABILITY_DRIVER_RC=1`、`STABILITY_ROUND_RC=0`、`STABILITY_GATE_RC=78`（diagnostic-only），没有采样器完成状态或 memory export。sampler 窗口为 900 秒；会话被页面 deadline 提前结束，R16 没有可用 RSS/PSS/USS 样本。不能用它证明关闭 trace 可以修复或保留采样时效，也不能据此比较 R15 的 158 次 missed。

原始证据：[evidence/2026-11-20_t490-r16-memory-only-control](../evidence/2026-11-20_t490-r16-memory-only-control/)。R16 screenshot 中 `stability/load-00-initial-timeout.png` 是全白画面；本轮三张 PPM 的 SHA-256 位于 [`evidence/_ppm-sha256-r16-memory-only-control.txt`](../evidence/_ppm-sha256-r16-memory-only-control.txt)，PPM 原件仅保留在 T490。

## 解释和下一步

R15 trace-enabled diagnostic reached strict page at 620.566 秒并通过 1/1 reload；R16 trace-disabled control 在相同 700 秒 ready deadline 内没有 strict page。两轮首屏结果方向相反，而 R16 没有跑满 900 秒 memory sampler 窗口，因此 trace 对采样 CPU 开销的影响仍未被单变量测定。

下一轮把 ready deadline 延长到 1200 秒，同时保持 trace 关闭、内存采样 900 秒及其余条件不变，以便 sampler 在页面超时前结束并回收原始内存包。该数据仍属诊断；若页面没有通过 strict，它不能作为页面加载后的 60 秒峰值窗口或正式四指标样本。
