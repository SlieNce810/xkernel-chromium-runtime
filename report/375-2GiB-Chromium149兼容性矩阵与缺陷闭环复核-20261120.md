# 2 GiB Chromium 149 兼容性矩阵与缺陷闭环复核（2026-11-20）

## 结论范围

本矩阵以 Chromium 最终 Browser-run 内核 SHA-256 `ac1032fe98c382cc37646a12453b7141b789c9abfe1651ff5f8f1e0263767fa2` 为主要对照。该二进制在 T490 AArch64、2 GiB、纯 TCG 上完成 focused ABI bundle，平台检查15/15，`compatprobe` 38/38、SCM_RIGHTS short-read 6/6、memfd sealing 12/12、procfs memory 九阶段有数值；指定首页与 Browser→Zygote→Renderer 父链另在同SHA上通过 strict 及4/4进程结构判据。主证据为 [report 343](343-Chromium149最终候选SHA首页与进程链复验-20261119.md)、[report 344](344-T490最终Browser-run内核兼容性矩阵复核-20261119.md) 和 [report 368](368-T490-procfs真实PSS-USS共享与COW统计复测-20261120.md)。

ABI小探针的PASS只说明该接口测试符合Linux；页面、真实输入和内存峰值结论仍以各自独立判据为准。

## 已修复缺陷的复现索引

1. **SCM_RIGHTS短读**：`compatprobe.c --scm-rights-shortread`；Linux首字节携fd；原x-kernel在首读/后续交付不符；修复源码与patch、24/24单测、6/6 guest C probe和浏览器fd行为均有证据（report333/334/344）。
2. **memfd sealing flags**：`compatprobe.c`的seal分支；Linux允许`MFD_ALLOW_SEALING`单独启用；原逻辑要求ALLOW与NOEXEC同时出现；修复patch和12/12对照在report342/344。
3. **MADV_DONTNEED跨VMA gap**：probe覆盖mapped-hole-mapped三页；Linux返回ENOMEM；原逻辑漏过gap并返回成功；修复patch、unit test和guest/native Linux对照在report342/344。
4. **MAP_PRIVATE文件页/PSS分类**：procfs memory probe触页、共享、fork/COW、unmap；原实现把clean file read页作为anon副本，file-shared统计不符Linux；页缓存/COW patch后精确候选数值见[report 338](338-MAP_PRIVATE页缓存共享与PSS-USS%20guest复测-20261119.md)和[report 368](368-T490-procfs真实PSS-USS共享与COW统计复测-20261120.md)。
5. **DRM render-node sysfs投射**：启动Ozone并检查`/sys/class/drm/renderD128/{dev,uevent,device,subsystem}`；原系统缺renderD128 sysfs链接；[patch 102](102-render-sysfs.patch)补齐后警告消失并由后续strict首页复核。
6. **`/proc/<pid>/stat` starttime 为零**：R2 采集器将 PID 5 标成 `5-0`，不能安全区分 PID 复用；修复 task 创建时钟与 stat field 22 转换，Linux `SC_CLK_TCK=100` 对照、R13 2 GiB guest `5-159`/`11-189` 回归及补丁见 [report 383](383-T490-proc-stat-starttime与进程树内存单遍回归-20261120.md)。

## 仍需单独判定的条目

- 2 GiB evdev真实输入依然失败，不能用4 GiB历史成绩代替。
- procfs standalone数据证明读取能力与COW共享计量，不是Chromium进程树的每秒RSS/PSS/USS峰值，也不判定1.5 GB资格线。
- 本矩阵不把可选配置目录的ENOENT、非法memfd flags的EINVAL、DRM软件渲染边界或部分沙箱探测写成已复现的内核缺陷。
