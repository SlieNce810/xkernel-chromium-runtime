## 采集器修正

本轮发现当前 C sampler 在没有 kernel timing META 的情况下，会在可选扩展列中输出字符串 `UNAVAILABLE`；旧 extractor 把它当作坏整数并拒绝有效的 RSS/PSS/USS 行。`extract_proc_tree_smoke.py` 现保留这些明确的不可用标记，并在摘要中写 `tree_snapshot_timing.available=false`；只有所有扩展字段一致地不可用时接受基础内存样本。半缺列、跨样本可用性变化、乱序/重复事件、缺内存行与非数值仍被拒绝。

同时，标准 `smaps_rollup` 的 `Shared=0` 是合法数值，不表示缺失；提取器继续要求 RSS 正数，并允许 PSS/USS/Shared 的显式非负数值。`test_extract_proc_tree_smoke` 10/10 通过，新增覆盖全组 `UNAVAILABLE`、半缺计时、Shared=0 和 USS=0；完整 Python 脚本测试集 77/77 通过。R48 运行后还把 smoke shell 的 `bad_values` 检查改为拒绝空/非数字、允许合法零 USS/PSS；该脚本在 T490 通过 `bash -n`，数值 0 测试通过、空字段测试拒绝。本轮所有值均非零，所以脚本小改动不会改变已记录结果。
