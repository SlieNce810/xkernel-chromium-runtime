# T490 R53 no-direct-PTE / ERROR-only 候选正式稳定性首屏超时（2026-11-21）

## 运行条件

R53 使用 no-direct-PTE 冻结派生候选，加 stat22、procfs RSS/PSS/USS/tree、dense PFN 与 timing 补丁；只调整 `.config` 将日志级别从 `LOG_LEVEL_WARN` 改为 `LOG_LEVEL_ERROR`，以减少正式验收中的逐次 futex/socket WARN 输出。kernel.bin SHA-256 `c78ecd57…ad017a67`，配置SHA-256 `1d0ff69e…c110419`。平台为T490、2 GiB、AArch64、QEMU10.2.1 pure TCG，platform check15/15。

formal stability runner 参数经过dry-run：10次reload/120秒、1805秒hold、默认2400秒readiness timeout、family watchdog15秒、process scan30秒；memory sampler、lifecycle preload、guest clock-sync关闭。

## 结果

官方HTML在完整2400秒readiness deadline内没有strict通过。Driver RC1，正式gate RC1；没有进入十次reload或30分钟保持。normalizer871/871通过，0修复；timeout末端Weston/Chrome仍存活，memfree约307 MiB。周期截图仅有240秒和1440秒两张，strict均未过；另有initial timeout截图。ERROR-only配置把console降到167,651字节，但没有恢复strict页面，说明降低WARN噪声有利于控制日志量，却不能单独修复候选页面启动。

## 与 R51 的区别和状态

R51是同一no-direct-PTE源码、`LOG_LEVEL_WARN`配置的observer-off诊断轮，页面strict、reload 1/1、420秒hold通过，但其normalizer因4个超过35秒的新鲜度门限的family snapshots失败。R53是正式10 reload/30分钟门槛配置，但使用ERROR日志，初始页timeout。由于日志级别和验收长度/保持方式不同，不能将两个结果当成直接单变量比较；no-direct候选仍表现出显著冷启动不稳定。

R53不构成稳定性PASS，也不包含内存采样或四项性能数据。下一步需要重跑no-direct候选并使用更轻、足够新鲜的family observer；只有strict首屏稳定通过后才能开始完整门槛轮。完整QEMU/命令/截图证据见 [R53 evidence](../evidence/2026-11-21_t490-r53-no-direct-error-formal/)；raw PPM保留在T490。
