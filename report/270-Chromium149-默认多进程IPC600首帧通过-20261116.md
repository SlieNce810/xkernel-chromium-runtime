# 270 · Chromium 149 默认多进程 IPC600 首帧通过（2026-11-16）

## 结果

在纯 TCG、guest 4 GiB、Wayland + Pixman + SwiftShader、in-process GPU 条件下，默认
browser → zygote → renderer 路径已经输出官方首页的有效 1280×800 页面帧。

证据目录：

`evidence/2026-11-16_t490-2026-11-16_t490-mp-wayland-ipc600-long/`

其中 `shot-08-at0886s.ppm` 经 `official-index` 严格像素判据验证为 7/7；人工复核确认
页面包含标题、四色块、表格、列表、SVG 和表单控件。此前相同条件下的 `shot-01`、
`shot-02` 是 Weston 初始化阶段的 640×480/启动画面，不能作为页面帧；从页面稳定出现后
的 1280×800 截图开始，像素内容保持一致。

## 根因收敛

默认 IPC 超时窗口不适合纯 TCG。renderer 进程在 zygote fork 后需要数百秒完成启动、
Mojo/ipcz endpoint、共享对象和 renderer 初始化；60 秒轮次会反复回收尚未完成 bootstrap
的子进程。将正式多进程入口的 `--ipc-connection-timeout` 固定为 600 秒后，renderer
进程账本出现稳定 PID，随后页面帧出现。

这不是单进程替代，也没有关闭 zygote 或把页面注入 browser 进程。页面仍由独立 renderer
进程完成解析、样式、布局和绘制，再经 compositor/Wayland 输出。

## 取证修正

- `autorun_mp_score_observe6.sh` 固定 IPC600，保留默认多进程参数；
- `t490_round.sh` 对官方 `index.html`、`layout.html`、`interaction.html` 自动选择对应
  `official-*` 像素 profile；
- 正式首帧轮把截图首点延后到 Weston 已切换为 1280×800 后，避免初始化阶段 640×480
  截图污染尺寸门禁。

## 当前边界

本报告只证明指定静态首页首帧恢复。双标签页/窗口、真实键鼠、JavaScript 交互和 CSS
布局页仍需在 IPC600 基线上继续验收；sandbox、稳定性、内存和性能门禁也尚未完成。
