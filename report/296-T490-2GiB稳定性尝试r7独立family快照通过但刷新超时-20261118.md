r7 完成了 strict 首页、1,805 秒保持和 10/10 次真实重载，60 条 hold liveness 均带完整 BrowserChild/ZygoteChild 角色；第六次重载正常通过。独立 `MP_FAMILY_WATCHDOG` 标记成功消除了多个 `MP_FAMILY` 写入源混读，但严格 gate 仍失败：有两条完整家族快照分别陈旧 39.763 秒和 69.807 秒，超过 35 秒新鲜度上限。

## 失败定位

严格规范化器报告 hold-window event `goal2g-stability-r7:220` 的 family age 为 39.763 秒，`goal2g-stability-r7:226` 为 69.807 秒；两个快照的角色集合完整，但快照太旧，仍不足以证明对应 liveness 时刻的 Renderer 家族存活。离线 gate 复核也在 liveness sample 16 报告 family snapshot stale。runner 因规范化失败跳过正式 gate，结论为 FAIL。

r7 的 driver 只消费 `MP_FAMILY_WATCHDOG`，而不是旧主扫描器和 watchdog 共用的通用 `MP_FAMILY` 行。console 与 event ledger 的 watchdog 快照数量均为72，角色缺失数降为0，证明来源分离解决了 R4-R6 的部分角色混读。剩余问题是 watchdog 家族快照刷新间隔偶尔过长。

66 条 skip diagnostic 全部是候选 Renderer PID 468、PPID 177 的 `proc_missing`；starttime 为0。原始 console 同时记录 PID 468 以退出码0结束，且同一时段的 watchdog 家族快照仍含其他 Zygote 子进程候选，因此该短命进程没有解释两条 stale family liveness。

## r8 刷新周期调整

watchdog 快照平均约29秒一次，未能保证每条30秒 liveness 都有35秒以内的新快照。下一轮把 family watchdog 计数阈值从10个 guest 秒调到4个 guest 秒，争取把新鲜快照间隔降到35秒以下；仍按 host 单调时间验证实际年龄。详细 skip 原因保持可开关，最终验收时再关闭该诊断输出复跑。

r7 结束后，hold-window 规范化器与标记解析器共19项 Python 测试通过；相关 shell 脚本 `bash -n` 和 Python `py_compile` 通过。平台预检 35 PASS、0 FAIL、1 WARN（kernel 工作树 dirty）。
