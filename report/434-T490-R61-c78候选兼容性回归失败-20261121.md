# T490 R61：c78 候选 focused 兼容性回归失败

## 结论

R61 在 2 GiB AArch64 pure-TCG 平台实际加载 c78 候选内核 SHA `c78ecd57fb47b8269ebecf0a4e99ee5d9f85648e01703726eee7af88ad017a67`。启动前干跑的 platform gate 15/15 通过，运行中的 QEMU `-kernel` 路径与 SHA 清单一致。

该候选不能替代当前 `compatibility-final` 通过的 `ac1032fe…` 内核：全量 `compatprobe` 35/37，SCM_RIGHTS 4/6，memfd sealing 6/12；procfs memory probe 返回 0，但共享字段存在不一致。核心失败有源码位置、Linux 预期和已知补丁对照：

| 缺陷 | Linux 预期 | R61 实际 | 涉及源码/修复方向 |
|---|---|---|---|
| inotify create 事件不可轮询 | `IN_CREATE` 可通过 `poll/read` 取得 | syscall 返回成功但无 create 事件（35/37 中一项） | `process/kfd_objects/src/inotify.rs`；对照 [compatibility matrix 375](375-2GiB-Chromium149兼容性矩阵与缺陷闭环复核-20261120.md) 的 inotify 实现和同源 probe |
| `MADV_DONTNEED` 跨未映射 gap | 返回 `ENOMEM` 且不部分丢弃已映射页 | 返回成功（35/37 中一项） | `mm/memspace/src/aspace.rs::MmSpace::madvise_dontneed`；补丁 [madvise-hole-ENOMEM.patch](../patches/compat/madvise-hole-ENOMEM.patch)，Linux 控制见 [report 344](344-T490最终Browser-run内核兼容性矩阵复核-20261119.md) |
| SCM_RIGHTS 首字节传递 | 首个成功 1-byte `recvmsg` 返回 fd，后续不重复 | 4/6；首字节无 fd，后续重复 fd | `net/knet/src/unix/stream.rs`；修复补丁及 Linux/guest 对照见 [report 333](333-SCM_RIGHTS首字节交付候选补丁与T490流回归-20261119.md)、[report 334](334-SCM_RIGHTS修复版guest短读复测-20261119.md) |
| memfd sealing | `MFD_ALLOW_SEALING` 后允许添加 seals；`F_SEAL_WRITE` 后写、扩容、缩容和共享可写 mmap 被拒绝 | 6/12；添加 seals 返回 `EPERM`，后续 seal 行为不符 | `posix/mm/src/memfd.rs::MemfdFlags::allows_sealing` 与 shmem seal 检查；修复 [memfd-sealing-flags.patch](../patches/compat/memfd-sealing-flags.patch)，Linux/候选回归见 [report 342](342-T490同一候选内核memfd与madvise兼容性修复-20261119.md) |
| 共享页计量可疑 | MAP_SHARED touched 页应在共享字段/PSS-USS 中有一致可解释变化 | probe rc=0，但 `statm_shared_pages=32`、`smaps_shared_kb=0` | `fs/filesystems/procfs/src/task_nodes/root.rs`、`mm/memspace/src/stats.rs`；与 Linux 九阶段值对照并补同字段回归 |

完整逐项输出、命令、内核构建指纹、平台检查及原始 PPM SHA 在 [R61 evidence](../evidence/2026-11-21_t490-r61-c78-compat-probe/README.md)。两张截图为 640×480 黑帧，round_assert 明确拒绝其作为决赛页面证据；R61 不是功能或稳定性通过。

## 对最终候选的影响

R61 是一个被拒绝的 no-direct-PTE ERROR 稳定性候选。R58–R60 在该内核上显示页并通过短保持，但这些结果不能覆盖本轮 syscall 失败。仓库的 `compatibility-final/summary.json` 仍指向 `ac1032fe…`，本报告不改写该摘要。

下一步应把缺少的 compatibility 修复与 no-direct-PTE、ERROR-only、procfs starttime/进程树统计改动合并到一个新候选；明确排除导致页面回归的 direct-PTE 优化；之后重建并重新跑 focused ABI bundle、Chromium 功能和正式稳定性。新候选通过兼容性 gate 前，不开始正式性能 before/after 批次。
