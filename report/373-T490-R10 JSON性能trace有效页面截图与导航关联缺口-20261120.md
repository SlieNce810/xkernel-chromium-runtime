# T490 R10：JSON性能trace和页面截图有效，导航关联仍有缺口（2026-11-20）

## 结论

R10完成了第10轮 Chromium startup trace诊断。基于T490 `10.249.11.192`、2 GiB AArch64纯TCG和Chromium 149.0.7827.53，页面严格判据通过，运行650秒后QEMU正常结束。串口trace完整抽取为30,055事件的JSON，3,969个连续块、gzip完整性、原始/压缩长度与SHA-256均通过。两张首屏截图显示指定HTML布局和颜色正常。

R10不能计为正式稳定性或性能样本：诊断门禁返回78，保持只有650秒、只配置一次reload，并启用了trace诊断开销。事件归一化419/419通过，页面严格判据在host单调时钟相对启动约528.289秒通过。

## 导航新鲜度发现

稳定性driver在QMP发送 `Ctrl+R` 后立即进入截图轮询。R10的导航请求发生在相对时间558.291秒，严格截图在559.078秒通过，仅间隔约0.787秒。静态测试页reload前后图像相同，因此单凭严格像素判据无法证明截图属于新导航。trace中第二条First Contentful Paint候选位于578.696秒；由于trace guest monotonic与driver host monotonic尚未建立时钟映射，这只是提示，不能直接声称发生了延迟或错误映射。

正式30分钟稳定性测试前应修正该门禁：对每次QMP导航施加最低等待窗后再开始严格截图采样，并将导航动作、截图时间和对应加载结果保存在同一事件账本。静态页面的截图相同属于预期；应以导航后时序保证新加载判据，而不是要求图像内容变化。

## Trace盘点

Trace元数据显示 `LINUX_CLOCK_MONOTONIC`，事件时间范围0至628.847秒。Browser PID为70，renderer PID为376和438。可见两个 `firstContentfulPaint` 事件，第一项为PID 376、时间526.065秒，第二项为PID 376、时间578.696秒。

`Startup.BrowserMessageLoopFirstIdle`从trace时间50.756秒开始、407.155秒结束；guest侧Browser启动标记为40.663秒。此事件是主循环就绪的候选边界，尚未完成语义和跨时钟核验。trace没有包含 `RenderProcessHostImpl::Init`、`RenderThreadImpl::InitializeRenderer` 或channel-ready事件，renderer创建时延不可用。此轮也没有采集Chromium进程树RSS/PSS/USS。因此四项性能指标仍无有效样本，before/after批次尚未启动。
