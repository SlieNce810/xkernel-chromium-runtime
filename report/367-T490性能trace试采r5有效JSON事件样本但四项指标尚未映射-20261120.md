# T490 Chromium startup trace 试采 R5：JSON事件样本有效，指标映射待完成（2026-11-20）

## 结论

R5修复了R4的默认protobuf格式问题：固定参数新增 `--trace-startup-format=json`，guard-only dry-run通过，Browser启动参数确认包含JSON格式开关。串口Exporter输出21,535个连续序号块（0–21,534），BEGIN/END块数一致；抽取器成功通过gzip、原始长度15,474,459字节、SHA-256 `3eee58e70673189a330d06d1ad67bcd272a7f5baca4fbb7f8d385a5c2e7d587f` 和JSON `traceEvents` 结构校验，共60,878个事件。

这是首个有效Chrome事件trace样本，但尚未把事件时间与 guest 单调时钟、导航编号、renderer 身份和对应页面判据关联，故启动时间、页面首帧延迟、renderer创建延迟及峰值内存仍为0个有效指标；before/after运行仍为0/0。事件名称计数不作为性能结论。

## 稳定性诊断结果

首页严格判据于590,704.849 ms通过；QMP重载1/1通过，保持550秒，driver pass=1。归一化372/372事件通过。周期截图间隔1200秒，因此只得到240秒的一张截图，发生在页面通过前，严格失败1张、post-pass失败0张；R5仍是diagnostic-only，gate RC78，不作为正式稳定性通过。

## Trace事件可见性

trace时间戳范围为0–625,931,512微秒。process metadata包含Browser、Renderer、Extension Renderer和三个服务进程。trace中可见DocumentLoader导航事件、FirstContentfulPaint、BeginMainFrame、SubmitCompositorFrame及Graphics.Pipeline等事件。逐项统计见 [R5 trace inventory](../evidence/2026-11-20_t490-candidate-perf-trace-r5/trace-events-inventory.txt)；这些统计只证明来源存在，没有证明测量口径或完成运行编号/导航关联。

性能采集下一步需：

1. 用Chromium trace startup/renderer事件确定Browser主循环ready、renderer创建请求/ready确认，以及对应导航的首次有效画面。
2. 通过明确clock sync事件或同域观测，把trace时间映射到guest单调时钟；为导航编号、PID重用和renderer身份设计拒绝歧义的校验。
3. 独立实现每秒进程树RSS/PSS/USS采样，覆盖启动到页面完成后60秒；trace事件不能代替驻留内存数据。
4. 四项指标单轮自检全通过后，再执行优化前后各至少5次冷启动。

完整材料位于 [R5 evidence](../evidence/2026-11-20_t490-candidate-perf-trace-r5/)；原始PPM保留在T490，仓库保存SHA清单和PNG预览。R5不构成性能样本批次，也不证明收益。
