# T490 R26 Browser 启动、导航上界与内存采样复测（2026-11-21）

## 结论

R26 使用冻结 kernel `da0c3802…de07f`、Chromium 149.0.7827.53、2 GiB AArch64 pure TCG、同一 pkg-installed 镜像、页面、virtio 键鼠和新版 lifecycle preload。首页 strict、1/1 真实 Ctrl+R 重载和 420 秒诊断保持均通过。

本轮得到一条有效的单轮启动观测：guest `CLOCK_MONOTONIC` 上 Browser 启动请求 `41.886868448 s`，`CrBrowserMain` 首次 poll/epoll 等待 `81.480916576 s`，启动延迟 **39.594048128 s**。这是本轮 lifecycle 事件直接相减的诊断样本，尚未进入有效性能 CSV。

指定页面导航 open 发生于 `165.373601968 s`。QMP 第一次 strict 通过截图映射到 guest `682.390683980 s`，间隔为30秒；从导航到该截图的**首帧保守上界是517.017082012秒**。QMP verdict 映射到 `682.398969742 s`。页面真实截图核验通过，但没有 `first_valid_frame` 或对应 renderer 身份，所以该数只作为单列上界，不当作精确首帧延迟。

renderer-create latency 仍不可用：探针记录了5个 Zygote fork boundary（guest 104.972、129.157、130.398、148.402、151.895秒），都早于本页导航；没有与本页 renderer 连接确认配对的 `renderer_ready`。采集器因缺 `renderer_ready`、`first_valid_frame` 拒绝整轮。

内存导出包已完整传输并校验，但 sampler 状态为 `FAIL`：220个 sample ID、1,370行、213 missed、271个错误，不能生成正式 RSS/PSS/USS 峰值或四指标性能样本。

## 下一步

正式统计前需先让 procfs sampler 在1 Hz口径下产生 `PASS`，并补到 renderer-ready 与真实帧来源。R26 的 Browser readiness 与导航事件可复用；Zygote fork boundary 仍保留为诊断事件，不能冒充 Browser 请求或 renderer ready。后续候选优化必须用单变量、重复运行验证，R23/R25/R26 的单轮时序差异不作为性能收益结论。
