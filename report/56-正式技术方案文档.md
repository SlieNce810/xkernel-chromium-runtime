## 1. 项目概述

**目标**：在 AArch64 QEMU 纯 TCG 软件模拟平台上，基于 Rust 编写的 x-kernel 构建可用图形运行环境，
启动 Weston 图形界面系统并运行 Chromium，完成窗口显示、网页加载与基本交互；同步完成内核
Linux 兼容性修复、可复现性能测量与全过程证据归档。

**结论摘要**（全部有归档证据，判定只认 screendump 与日志）：

|---|---|

| 指定页面 | 官方 index 严格像素判据 **7/7 × 10 张**通过（`strict_fail=0`） |

## 2. 技术方案与架构

### 2.1 总体栈

```text
QEMU 10.2.1（aarch64 virt, cortex-a76, 2 GiB, 4 vCPU, 纯 TCG）
├── virtio-gpu-pci ──► x-kernel DRM 子系统（simpledrm/card0, ioctl 面）
├── virtio-blk-pci  ──► kext4 根文件系统（agentos 镜像 + 每轮注入）
├── virtio-net-pci  ──► knet（user 网络，hostfwd 5555）
└── virtio-input    ──► evdev（/dev/input/event*，sysfs 投影 + uevent）
guest 用户态：
  seatd（libseat 后端）── Weston 14.0.2（drm-backend.so + pixman renderer）
      └── Wayland 协议（wayland-1 socket）
          └── Chromium 142.0.7444.59（Ozone/Wayland 平台，单进程模式）
                └── file:///usr/share/html-test/index.html（组委会指定页面）
```

### 2.2 关键设计决策

1. **单进程浏览器路线**：`--single-process --no-zygote --in-process-gpu`。x-kernel 的多进程
   clone/exec 语义在项目期内未完全对齐（renderer 子进程创建仍失败），单进程路线用最小内核面
   换取"窗口创建 + 页面加载 + 稳定运行"的完整闭环；多进程探索轮（`mp-*`，09-27~10-02）留存 T490。
2. **软件光栅**：`--use-gl=angle --use-angle=swiftshader`（overlay 提供 Vulkan ICD），
   不依赖 virtio-gpu 3D（host 无对应加速且评分要求纯 TCG）。
3. ** Weston 无输入容错**：`--continue-without-input` + 输入设备就绪等待。内核 virtio-input
    **事件消费链**是已知缺口（设备可枚举、事件不上送），应用层输入经 CDP/页面事件验证通过；
    Weston 不因无输入设备而 fatal，保证图形会话稳定。
4. **证据优先的编排**：每轮固定产出 console.log（串口+monitor 全量）、screendump（唯一认可的
   功能证据）、build-manifest（内核/镜像/页面/脚本指纹）、env.txt（宿主指纹）、
   platform-compliance（纯 TCG 硬断言）。判据工具 `ppm_assert.py` 对原始 PPM 逐像素断言，
   不依赖肉眼。

### 2.3 内核侧改动（8 项缺口 → 17 个补丁候选）

| # | 缺口 | 修复要点 |
|---|---|---|
| 1 | fd 表下界 + zygote fd 继承语义 | fd 表容量与继承语义对齐 |
| 2 | Unix socket ancillary（SCM_RIGHTS/CREDENTIALS/CLOEXEC）与 DGRAM/SEQPACKET 半关闭 | cmsg 解析补全 |
| 3 | `ppoll_time64` 分派 | 系统调用分派表补项（缺失时 musl 收 ENOSYS → FATAL） |
| 4 | procfs 字段（线程数/状态/内存/uptime 动态值） | `/proc/self`、`/proc/stat`、`/proc/uptime` 等 |
| 5 | `PR_SET_PDEATHSIG` 最小 ABI | prctl 分支补全 |
| 6 | TCP keepalive 选项（KEEPIDLE/INTVL/CNT） | socket 选项解析 |
| 7 | futex PI 未实现（EOPNOTSUPP 回退）+ RLIMIT_NOFILE 65536 vs fd 表 1024 | 用户态配套 |
| 8 | virtio-input 事件消费链未打通 | 设备可枚举；事件消费为已知缺口（如实记录） |

缺口材料按“现象 / 最小复现 / Linux 对照 / 影响 / 补丁或限制”五要素整理；逐条复现与范围说明见 report/60。
上游 [PR !831](https://gitee.com/openkylin/x-kernel/pulls/831) 为已合并的构建文档路径修复（2026-09-22 15:03:43，北京时间；落点 `0a04f7dcb99b18b93c83e6829d8eeb72efcab1ea`），用于说明开源协作成果，其余候选见 `report/patches/`（0001–0018，缺 0008）。

## 3. 实现要点

- **构建配置单一真源**：`scripts/t490/platform.env`（`GRAPHIC=y ACCEL=n MEM=2g SMP=4 VSOCK=n`，
  输入设备 `--with-input`）；内核 `.config` 取组委会基线（sha256 `42e8d164…`，与基线重展开
  逐字节一致），存档于 `evidence/2026-09-22_t490-stage0-freeze/src-snapshot/.config`。
- **guest 运行时 overlay**：`guest-overlays/eudev-seatprobe-libinput-swiftshader-p31.tar.gz`
  （16 MB，57 项：eudev/seatd/libinput/SwiftShader ICD），每轮由 autorun 解包。
- **轮次编排**：`t490_round.sh` 复制基准镜像 → 注入 autorun/pages/overlay → `make run` 起
  QEMU → monitor screendump → 收尾归档（含 guest 日志 dump）。同名 tag 同日重跑会覆盖，
  脚本有防护；失败轮保留不删。
- **判据体系**：`scripts/t490/ppm_assert.py`（官方三页像素判据常量来自
  `scripts/testpage/reference/` 参考图）+ `round_assert.sh`（尺寸一致性、心跳、汇总 GATE）。
- **测量体系**：`measure-single-initial.sh`（5 轮、每轮新 QEMU/新 profile）+
  `collect_single_metrics.py`（指标收集）+ `observe_qemu.py`（host /proc 观测）+
  `measure.py`（中位数/极差/`--baseline` 改善注解）。

## 5. 性能测量与 before/after

### 5.1 方法（§七(二) 合规）

- 每项指标 **≥5 次**取中位数并给波动范围；原始数据 `raw.csv` + 汇总 `summary.json`。
- 宿主指纹（CPU 型号/内存/QEMU 版本/OS）逐轮入 `env.txt`/`host.txt`。
- 指标按五组列出：① 首次发现导航开始日志的采样计数 ② 首张通过判据的定时 screendump 时刻
  ③ 稳定保持时长 ④ 峰值内存（host QEMU RSS，标注 host 观测）⑤ CPU 使用率（host /proc 采样，
  单核尺度百分比）。
- 口径说明（重要）：`first_nav` 为 15 s 采样粒度的真实观测（TCG 确定性高，五轮同值属预期）；
  `screendump` 时刻由 `FIRST_SHOT=180` 固定；`hold` 为固定窗口。内存/CPU 为 host 侧
  QEMU 进程观测（guest `/proc` 的 VmRSS 不可用，未写成有效内存结论）。
- 日志与定时截图不等同于真实首帧/页面加载完成耗时，保持窗口不自动计为独立性能类别。未适配器的 baseline 无有效页面性能样本；共同 PI 中和适配器下 before/after 各五轮，但四项指标均未达到 5% 改善档位，详见 [历史失败说明](57-性能before-after配对测量报告.md) 与 [共同栈实测](64-共同用户态适配器before-after五轮实测.md)。

### 5.2 内核二进制哈希口径

内核镜像内嵌 `build_time`/`build_id`，**同源码多次构建 sha256 不同**（已实测：
`dcb862c9`/`7584653b`/`2f873528`/`d58ba99b` 均为 `2a1b101` 内容）。tag 存档的是**源码**
（`v0.1-first-runnable`=`f8b9224` 等），各轮实际哈希记录于该轮 `build-manifest.txt` 与横幅。

### 5.3 before/after 配对测量（基线 = 首个可运行版本）

- 基线：tag `v0.1-first-runnable`（`f8b9224`），同镜像同 overlay 同脚本，5 轮。
  **结果：Weston 可起（`--continue-without-input`），Chromium 启动后即中止**
  （PulseAudio `pa_mutex_new` 断言失败 + crashpad `missing credentials`），
  `single_gate=0`、`page_assertion=0` 各 5 样本——页面加载未完成。
- 当前：`2a1b101`（构建 `d58ba99b`），5 轮，页面加载完成（详见 `report/57` 数据表）。
- 未适配器运行栈下的结论口径：基线**无法产出页面加载指标**（非“慢”而是“未完成”）；当前版本可完成页面加载，因此这是功能性跃迁，不据此计算性能百分比。原始失败现场保留，见 report/57。共同 PI 中和适配器下的配对实测另有 before/after 各五个通过样本，但四项指标均无 5% 改善分证据，见 report/64。
