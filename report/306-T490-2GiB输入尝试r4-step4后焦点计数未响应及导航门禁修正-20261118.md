# T490 2 GiB Input R4：step4 校准后仍无回显/计数，修正 CSS 导航门禁

## 结论

R4 在 2 GiB 默认多进程下通过 `official-interaction` 页面 ready 和 JavaScript 自检，但真实文本输入回显、鼠标计数点击仍未通过，Input 继续记为 0/4；当前 2 GiB 浏览器功能总分维持 16/20。统一入口的 isolated `input` stage 记为 0/20、rc=1，因为该轮只运行 Input 且 Input gate 失败；它不是整套功能总分。此轮把 HMP 鼠标切换为历史 step4 校准路径：先激活窗口，再用 4 像素步进定位并对控件双击。事件 ledger 记录 20 个 QMP 键盘动作、5 次 HMP 点击、549 次 HMP 相对移动；这些是控制接口动作记录，截图像素仍是判据。

R4 首次 gate 把“mouse navigation”判成通过，但输入后截图实际仍显示 `interaction.html`。原因是旧子门禁只检查绿色结论条；JavaScript 自检页面也有绿色结论条。对同一原始 `after-mouse-navigation.ppm` 用 `official-layout --strict` 重算，严格集只有 2/5 通过，C1 Flex、C2 Grid、C3 盒模型均缺失。修复后的 gate 要求完整 `official-layout` strict 集与布局页结论条同时通过；回归测试覆盖“绿色结论条不能单独证明已导航”。

## Gate 修正与验证

旧 `interaction_score_gate.py` 的 `layout_verdict()` 只看绿色结论条，导致 R4 的 JavaScript 绿色条被误判为 CSS 页面结论。现在该函数调用 `ppm_assert.py --profile official-layout --strict`，并另外确认布局结论条；strict 结果保存在新的 `.layout-strict-validation.json` 文件，原始输出未被覆盖。

新增 [test_interaction_score_gate.py](../scripts/t490/test_interaction_score_gate.py) 验证绿色结论条但 C1/C2/C3 失败时必须拒绝导航。两个回归测试均通过。
