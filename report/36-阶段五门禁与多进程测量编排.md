## 默认多进程门禁

`autorun_mp_diag.sh` 的 Chromium 命令明确不含 `--single-process` 和 `--no-zygote`。脚本会：

1. 记录 Weston socket、输入节点和 compositor PID；
2. 记录完整 Chromium argv；
3. 每 5 秒记录 `type=renderer`、zygote、utility、GPU process 的 PID、线程数、`wchan` 和 maps 行数；
4. 记录 Chromium 进程 RSS 总和；
5. 记录 `MP_RENDERER_FIRST_EPOCH_MS`、`MP_RENDERER_MAX_STREAK` 和 `MP_GATE`；
6. 只有 renderer 连续出现至少 12 个采样点，即约 60 秒，才写入 `MP_GATE=1`。

`MP_TRACE=1` 时才从 Chromium 启动前包住 `strace -ff`。strace 轮不进入性能统计，只用于判定 clone/exec/wait/futex/Unix socket/memory 路径。

## 测量编排门禁

`measure-all.sh` 默认运行 5 轮、每轮 660 秒、60 秒截图间隔，入口页默认为 `index.html`。每轮使用唯一 tag 和独立证据目录，依次执行：

```bash
bash scripts/t490/t490_round.sh <tag> 660 60 autorun_mp_diag.sh
python3 scripts/collect_metrics.py <evidence> --run <n> \
  --csv <output>/raw.csv --profile official-index
python3 scripts/measure.py <output>/raw.csv <output>/summary.json --minimum 5
```

只要会话、renderer gate 或官方页面判据有一项失败，脚本会保留该轮 evidence 并退出，不生成“通过”的统计汇总。这样不会把单进程页面或没有 renderer 的启动时间混入正式性能样本。

## 恢复 T490 后的执行顺序

1. 恢复 SSH 公钥认证，记录 T490 `git rev-parse HEAD`、工作树状态、kernel image 和基础镜像 SHA-256；
2. 跑一轮 `MP_TRACE=1` 的短诊断，确认 renderer 缺失位于创建前还是创建后；
3. 根据 trace 只改一个内核接口，重新构建并跑 180 秒对照；
4. renderer gate 通过后，用 `MP_TRACE=0` 连续跑 600 秒，完成三页、输入和页面结论条验收；
5. 通过功能门禁后再运行 `measure-all.sh`，生成 before/after 原始 CSV、汇总 JSON、宿主机指纹、perf/eBPF 和火焰图目录。
