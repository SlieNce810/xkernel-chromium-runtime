## 二、环境与依赖（全部脚本化，位于 `scripts/wsl2/`）

| 依赖 | 版本/来源 | 安装方式 |
|---|---|---|
| QEMU | 8.2.3，源码编译 | GitHub `--depth 1 --branch v8.2.3 --recurse-submodules`；`--target-list=aarch64-softmmu --enable-slirp`；装到 `~/qemu-8.2.3`（`build_qemu.sh`） |
| rust target ×2 | `aarch64-unknown-none-softfloat`（内核 no_std）+ `aarch64-unknown-linux-musl`（uapp std） | `rustup target add`（`build_xk.sh` 步骤 0） |
| musl 交叉工具链 | aarch64-linux-musl-gcc 11.2.1 | musl.cc 直下（`prepare_user.sh`） |
| x-kernel | gitee main @ `88f8b50` | cargo 构建（首次全量约 2 分钟） |
| rootfs | alpine-busybox 预构建镜像 | gitee release（压缩 9.5MiB，扩容至 4G） |
| 编译依赖 | ninja/glib/pixman/fdt/slirp-dev | WSL 内已齐备（`apt_deps_root.sh` 幂等） |

构建命令（固定流程，`build_xk.sh` 一键）：
```bash
cp platforms/kplat-aarch64/qemu_defconfig .config
make defconfig
make rootfs ROOTFS_VARIANT=alpine-busybox
truncate -s 4G disk.img && e2fsck -f -y disk.img && resize2fs disk.img
make uapps          # debugfs 注入 hello/mini-oci/weston-start + autostart 钩子
make build
make run GRAPHIC=y ACCEL=n MEM=4g SMP=4 VSOCK=n --with-input(虚拟键鼠)
```

## 三、问题清单与修复（今晚实战沉淀）

### 3.1 已解决
| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | QEMU 源码国内无镜像（TUNA/USTC/华为云均无） | — | GitHub git clone（该 WSL 内可达）；tarball 无 meson 子模块，必须 clone |
| 2 | `roms/edk2` 子模块递归 clone 失败 | edk2 巨大且不需要 | deinit 掉，configure 不受影响 |
| 3 | WSL2 启动 QEMU 失败：`vhost-vsock: failed to open` | WSL2 内核无 vhost_vsock 模块 | **`VSOCK=n`**（vsock 不在赛题设备组合内） |
| 4 | 串口敲命令丢字符（`sh /root/autorun.sh` → `sh/root/autorun.sh`） | TCG 忙时 tty 输入丢字节 | 一切 guest 内操作走 **autostart 注入**（debugfs 写 99-autostart.sh），绕开串口输入 |
| 5 | 注入的 autostart 段不执行 | 原脚本 `start_foreground ... \|\| return 1` 短路 | 注入段放**最前**；移除原 weston-start 行 |
| 6 | 强杀 QEMU 后镜像损坏（busybox 读出 0 字节） | guest 侧 writeback 数据在 QEMU 死时丢失 | **guest 内关键阶段后 `sync`**；停机用 Ctrl-A x；每次 debugfs 直改后 `e2fsck -f -y` |
| 7 | `debugfs write` 报 `Ext2 file already exists` | write 不能覆盖 | 先 `rm` 再 `write` |
| 8 | debugfs 直改后出现孤儿目录/共享块 | debugfs 不写 journal | `e2fsck -f -y` 修复（可自动痊愈） |
| 9 | 会话进程随 wsl.exe 退出被杀 | wsl.exe 会话生命周期绑定 | **`setsid -f`** 启动，脱离宿主进程 |
| 10 | rust 编译 uapp 报 `can't find crate for std` | 只装了 no_std target | 补 `aarch64-unknown-linux-musl` |

### 3.2 未解决（明天 T490 主攻）
**Weston DRM backend 无法打开 card0**。两条失败形态：

- 形态 A（会话 1，autostart 前台首跑）：
  ```
  [libseat/libseat.c:73] Seat opened with backend 'seatd'
  libseat: session control granted
  ERROR: could not open DRM device 'card0'
  fatal: failed to create compositor backend
  ```
  → seat 会话正常，**open("/dev/dri/card0") 失败**。节点存在（crw-rw-rw 226:0），
  root 权限下 open 失败指向 **x-kernel VFS/devfs 的 DeviceFile open 路径**或 card0 内部
  `primary_scanout()` 空注册表（NoSuchDevice）。
- 形态 B（会话 6，重试循环中）：
  ```
  Backend 'seatd' failed to open seat, skipping
  Backend 'logind' failed to open seat, skipping
  fatal: failed to create compositor backend
  ```
  → 多次重试后 seatd 残留进程/socket 状态污染，**调试时应每轮清理 seatd**。

**排查计划（T490，按序）**：
1. 干净单次尝试：`pkill seatd; rm -f /run/seatd.sock; seatd -g root -l debug &` 后手动起 weston
2. 用 libdrm 工具隔离 ioctl 层：`apk add libdrm-tools && modetest -M simpledrm -c`
   （能枚举 connector 说明 open+VERSION+GETRES 正常，问题在 weston 的 seatd 集成）
3. 检查 `/proc/devices` 是否有 `226 drm`；`ls -l /sys/class` 确认 display 类设备注册时序
4. 若 open() 报 ENODEV → card0 的 `scanout_available()` 在 devfs 挂载时为假但节点已注册的
   **时序竞争**（devfs 快照语义 vs virtio-gpu probe 顺序）→ 给上游提 issue + patch
   （**正是赛题 25 分「兼容性缺口与补丁」的素材**，候选缺口清单 +1）
5. fbdev 路线已证伪（Weston 14 无 fbdev backend），不再投入
