# T490 2 GiB 输入尝试 R18：step3 计数与导航仍失败

## 结论

R18 在 T490 上以 2 GiB guest、AArch64 纯 TCG、Chromium 149 默认多进程运行。交互页在第 47 次 readiness 采样通过；JavaScript 自检和键盘回显通过。鼠标计数仍显示 0，CSS 链接未打开布局页，严格交互 gate 因此失败，Input 仍为 0/4，总分仍为 16/20。

本轮向 HMP 相对鼠标发送 640 次移动、5 次点击。计数候选目标为 `(250,588)`，点击后截图仍可见计数 0，光标位于计数按钮下方。CSS 链接点击后截图仍为交互页；计划中的 3 次 PageUp 没有在布局页上验证，不能据此判断 PageUp 是否能修复 CSS 页截屏位置。QMP 以 rc=0 正常退出，input driver 和 round orchestrator 均返回 0，但评分 gate 返回 1。

后续校准时对原始 `after-scroll.ppm` 与 `after-mouse-click.ppm` 做逐像素差分，隔离到 82 像素的指针变化分量，bbox 为 `[302,729,311,743]`，热点约 `(302,729)`。按同一方法复核 R17，R17 请求 `(212,638)` 的热点为 `(253,724)`；R18 请求 `(250,588)` 的热点为 `(302,729)`。用这两点作线性外推，计数按钮中心 `(280,674)` 的下一候选请求为 `(233,1138)`，CSS 链接中心 `(350,710)` 的候选请求为 `(287,778)`。它们仍是单次路径下的校准候选，页面状态、指针路径或加速行为变化时可能失效；下一轮必须先看真实截图再判点击结果。

## 复现参数

```text
env -u PLAT_MEM_OVERRIDE EVDEV_PROBE=0 INTERACTION_POINTER_MODE=step3 INPUT_NAVIGATION_WAIT=60 MULTIPROCESS=1 FORCE_HMP=1 ABS_POINTER=0 NO_CLAMP=1 EXTRA_FLAGS_VALUE=--js-flags=--jitless READY_TIMEOUT=2000 bash scripts/t490/run_input_final.sh codex-2026-11-18_231427-input-step3-adjusted-counter-pageup 2400 60
```

R18 使用的计数请求 `(250,588)`、CSS 链接请求 `(350,710)` 均未通过；不能把它们视作已校准坐标。导航后的 3 次 PageUp 是计划动作，但截图没有进入 CSS 页，因此该动作不构成 CSS 布局回归验证。下一轮的 `(233,1138)` / `(287,778)` 来自两轮截图热点的线性外推，仍待实际验证。driver 现在也支持 `INTERACTION_COUNTER_TARGET=x,y` 与 `INTERACTION_NAV_TARGET=x,y` 覆盖值，供后续记录单变量尝试。
