# T490 2 GiB 输入尝试 R8：交互页再次 ready 超时

## 结论

R8 在赛题默认 2 GiB、AArch64 纯 TCG、Chromium 149 默认多进程条件下再次未能通过 `official-interaction` 页面 ready gate。`READY_TIMEOUT=2000` 秒内保存 187 张 readiness 截图，最终仍缺 `official_banner` 与 `interaction_checks_table`；正式会话的 28 张 QEMU screendump 全部未通过 strict 页面判据，首尾查看图均为灰白空帧。输入 driver 没有启动，因此本轮没有发送键鼠动作，不能据此评价鼠标或键盘链路；2 GiB 功能状态仍为 16/20，Input 为 0/4。

串口中可见 Browser PID 71 与多个 Zygote PID 的 IPCZ 收发，说明浏览器进程仍在活动。日志中的 `MP_RENDERER_COUNT=0` 来自本轮轻量 `ps` 采样器；当前 T490 输出缺少完整 argv，该值不能证明没有 Renderer。

事后配对内核已有的有界 `CHROMIUM_FUTEX_CALL/RESULT` trace：前 4,096 次调用里解析到 4,095 个 call、4,084 个 result，配对 4,083 条；其中 `FUTEX_WAIT` 有 429 次 `WouldBlock`、613 次 `TimedOut`、3 次 `Interrupted`、840 次 `Ok(0)`，`FUTEX_WAKE` 有 1,371 次 `Ok(0)` 和 827 次 `Ok(1)`。Linux futex 文档规定 wait 时值不匹配返回 `EAGAIN/EWOULDBLOCK`，有限 timeout 到期返回 `ETIMEDOUT`，因此这些 wait 结果本身是正常竞态/超时语义，不能解释为空帧根因。[futex trace 汇总](../evidence/2026-11-18_t490-codex-2026-11-18_172923-input/futex-trace-summary.json)。[Linux `FUTEX_WAIT(2)` 文档](https://man7.org/linux/man-pages/man2/FUTEX_WAIT.2const.html)

完整串口仍记录大量通用 `SANDBOX_SYSCALL_ERROR` 行（`TimedOut=95,805`、`WouldBlock=657`、`Interrupted=4`、`OperationNotSupported=1`）。这些计数是全程分派日志，不都能与有界 call trace 配对。唯一的 `OperationNotSupported` 来自 Browser PID 71，但 dispatch 行没有操作码；内核 `core/ksyscall/src/sync/futex.rs::sys_futex` 对 PI futex 命令显式返回 `OperationNotSupported`，源码注释说明 musl 会用此路径探测并回退普通 mutex。这个样本与能力探测相符，但由于缺少该次调用参数，只能列为“可能的能力探测”，不能定为已确认。更完整的 parser 输出与原始数据见证据目录；当前仍没有证据把该项或大量 wait 返回映射到页面空帧。

本轮启动了裸 evdev sniffer，串口确认它打开前被安排监听 `/dev/input/event0`、`event1`。但 driver 在 ready gate 后才运行，本轮没有注入输入，且 `/root/mp-evdev.log` 没有进入停机后的 guest 日志回收结果；所以没有可用的 evdev 事件计数。下一轮会让探针事件直接镜像到串口，并改进 `/proc` 进程身份记录，避免把不可见的 Renderer 误报为不存在。

外层 WSL `final-acceptance.sh input` 在远端 QEMU 和轮次脚本结束后仍等待 SSH 返回；再次确认 T490 上没有 QEMU 或轮次进程后，本地等待连接已终止。外层 `input.log` 只记录到调用开头，没有生成 `acceptance.json`；会话结论以远端完整 console、manifest 和 `ppm-summary.txt` 为准，外层材料单独保留为 transport 异常证据。

T490 上实际调用为：

```bash
env -u PLAT_MEM_OVERRIDE MULTIPROCESS=1 FORCE_HMP=1 ABS_POINTER=0 NO_CLAMP=1 \
  EXTRA_FLAGS_VALUE=--js-flags=--jitless READY_TIMEOUT=2000 \
  bash scripts/t490/run_input_final.sh codex-2026-11-18_172923-input 2400 60
```

R8 时 T490 的 `run_input_final.sh` SHA-256 为 `127f0c54d69c5b5ead94b167c370680e549dd4dc8b5c65aea72ca15745620a7a`，仓库当前版本为 `74f071326b3df2893aa8f28ed92bcfc0b0da82ac8afe2e5e74291821424caca9f`。因此 R7 后把全程截图 `STRICT_GATE` 设为 0 的仓库改动并未同步进 R8；本轮在 ready gate 已失败后退出，该差异不改变 ready 结论。下一轮开始前需核对并记录工具脚本哈希。
