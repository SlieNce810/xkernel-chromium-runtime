# T490 2 GiB 输入尝试 R9：交互页 ready 通过，键盘回显延迟，鼠标未通

## 结论

R9 在默认 2 GiB、AArch64 纯 TCG、Chromium 149 默认多进程下，于 ready 第 45 次采样通过 `official-interaction` strict gate。本轮设置 `EVDEV_PROBE=0`，不注入 evdev sniffer；QEMU 会话在 742.2 秒后以 QMP quit 正常结束。统一平台检查 15/15 通过，Browser 和 Zygote IPC 活动可见。

交互 driver 记录了 20 个 QMP 键盘动作、5 次 HMP 点击和 549 次 HMP 相对移动；JS 自检最终显示 6/6。固定在输入后 30 秒保存的 `after-keyboard-echo.ppm` 仍显示自检运行中、文本框未回显，所以 gate 报 keyboard echo FAIL；后续 `after-mouse-click.ppm` / `after-mouse-navigation.ppm` 已显示输入框和回显区均为 `hello x-kernel`。这说明键盘回显发生得比 30 秒采样晚，但本轮没有用同视口的配对截图通过 gate，Keyboard 仍不能计分。下一轮将延长并轮询键盘回显判据。

鼠标计数仍为 0：driver 按页面截图目标 `(281,674)` 执行真实 HMP 点击后，计数截图没有变化。导航仍停留在 `interaction.html`，因为本轮导航点击目标 `(500,710)` 偏离截图中的 CSS 链接；后续已把目标修正为 `(350,710)`。本轮没有启动 evdev sniffer，因此不能判断 HMP → virtio-mouse → evdev 的哪个环节丢失事件。Input 仍为 0/4，2 GiB 总分仍为 16/20。

R9 只证明本轮无 sniffer 时页面能通过 ready。R5 曾在同样无 sniffer 的条件下超时，R8 启用 sniffer 也超时；R7、R9 无 sniffer 则通过 ready。因此现有轮次不足以认定 sniffer 导致或避免冷启动失败。下一轮启用已改为串口输出的 evdev 旁路采样，并按修正后的键盘等待和 CSS 链接坐标复测。
