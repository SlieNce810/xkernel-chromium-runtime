# T490 2 GiB 输入尝试 R11：键盘回显通过，鼠标计数门禁校正

## 结论

R11 使用 `EVDEV_PROBE=0`，在第 56 次采样通过 `official-interaction` strict ready。新键盘回显轮询在第一次 10 秒截图就检测到输入 ROI 变化；`after-keyboard-echo` 显示输入框与回显区均为 `hello x-kernel`，自检结果为 6/6。Keyboard 子 gate 通过。

鼠标计数仍未发生。R11 as-run gate 的 `mouse_counter_diff=true` 是旧的宽 ROI 捕获到光标移动造成的误通过；截图显示计数仍为 0。事后把 ROI 收窄到计数文字区域 `(220,625)-(600,655)` 后，`interaction-score-gate-corrected.json` 重算为 `mouse_counter_diff=false`。更新后的单元测试覆盖这个 ROI 边界。CSS 导航仍未通过，导航后截图继续是 `interaction.html`。

R11 截图还定位了 step4 相对指针的坐标漂移：命令请求计数按钮 `(281,674)`，截图中的鼠标光标约在 `(320,749)`，落在按钮下方；导航点击也命中页面底部附近而没有点中 CSS 链接。已把下一轮候选坐标校正为计数按钮 `(247,607)`、CSS 链接 `(292,638)`，仍需独立复测。HMP 真实动作 ledger 记录 20 键盘动作、5 次点击和 512 次相对移动，但这不能替代像素判据。Input 仍为 0/4，2 GiB 功能总分仍为 16/20。

## 门禁修正与复现

as-run 文件 `interaction-score-gate-run.json` 保留旧 ROI 的结果；事后按新计数 ROI 重算得到 `interaction-score-gate-corrected.json`。新 ROI 只覆盖计数文字，不包含按钮、页脚或鼠标光标，所以光标移动不会再被当成计数变化。回归检查见 `scripts/t490/test_interaction_score_gate.py`。

本轮实际命令：

```bash
env -u PLAT_MEM_OVERRIDE EVDEV_PROBE=0 MULTIPROCESS=1 FORCE_HMP=1 \
  ABS_POINTER=0 NO_CLAMP=1 EXTRA_FLAGS_VALUE=--js-flags=--jitless READY_TIMEOUT=2000 \
  bash scripts/t490/run_input_final.sh codex-2026-11-18_195844-input-noprobe-echo-wait 2400 60
```

下一轮候选鼠标目标为：

```text
counter button:  (247,607)
CSS layout link: (292,638)
```

这些值按 R11 截图中观测到的光标偏移估算，尚未通过新的独立输入轮确认。
