# T490 Chromium 启动 trace 试采 R1：页面诊断通过，trace 参数未注入（2026-11-20）

## 结论

本轮 diagnostic-only trace 探针请求在 Chromium argv 中加入 `--trace-startup`、指定 `/root/mp-perf-trace.json` 并运行500秒。但实际 `CHROME_ARGS` 日志没有 trace 参数，guest 回收目录也没有 `/root/mp-perf-trace.json`。因此这轮没有 Chromium 内建 trace 数据，不能作为四项性能指标样本。

稳定性诊断本身通过：初始首页在 driver 启动后496.869秒 strict PASS；nav-01真实 QMP `Ctrl+R` 重载通过；保持550.0秒，1/1次重载通过。周期截图27/27成功，首个周期 strict 帧是 `shot-10-at0512s`，其后周期 strict 失败为0。事件归一化376/376通过，292条 watchdog 中 Weston/Chrome均为`yes`；最后 guest uptime 1,045秒、memfree 532,428 KiB。Driver和round RC0，正式 gate 按 diagnostic-only 设计返回 RC78。

根因是 `t490_round.sh` 虽会替换 `EXTRA_FLAGS_VALUE`，但此轮使用的 `autorun_mp_score_observe6.sh` 没有 `EXTRA_FLAGS` 占位符或相应的 `CHROME_ARGS` 拼接，所以 trace 开关没有传到 Chromium。该模板已在后续工具修复中增加占位符与参数拼接；`run_chromium_trace_probe.sh` 的 preflight 会在启动前验证这段注入路径。该修复尚未由一轮有效 trace 文件验证；R1仍标记为“无trace试采”。
