# T490 R10 kernel 短间隔八次重载控制通过（2026-11-19）

## 结论

在隔离的 baseline 副本中使用精确 kernel binary SHA `51c4028594e4aff9fc5b9964c4294a2904621c93e84093ac711858c454aed284`，以 2 GiB AArch64 纯 TCG、相同 rootfs 和 Chromium 149 完成短间隔控制：初始首页 strict 在 465.922 秒通过，随后 8 次 QMP `Ctrl+R` 全部 strict 通过。八次加载的间隔为 30 秒，driver 计时 240.748 秒。

该结果不是正式稳定性验收：`STABILITY_DIAGNOSTIC_ONLY=1` 跳过了 1,805 秒保持和 10 次重载 gate。它证明在这组压缩的重载序列中，精确旧 kernel 没有重现候选 `ac1032fe…` 的 nav-08 “Page Unresponsive”；目前的证据把排查范围收窄到候选 kernel 相对 R10 的变化，但还不能确定是哪一项兼容性补丁造成。

## 固定条件与复现

- T490 `10.249.11.192`，QEMU 10.2.1，AArch64、`-m 2g`、4 vCPU、纯 TCG、1280×800 virtio GPU/keyboard/mouse、Weston/Wayland。
- rootfs SHA-256 `bab5c9f5dbf1e4a910bab569635bb9e44fe38c3b8cea94ae8eae4ce3f7a9fdb1`；Chromium 149.0.7827.53，可执行文件 SHA-256 `d7d89bcb466c1d9a7ab209220c8ab997f66c02b77c5e80d3ea10ed64c772a641`。
- `KERNEL_DIR=/home/mo/xk6/worktrees/xk-stability-baseline-r1`，`XKMAKE_ARGS=--no-build`；build manifest 确认 QEMU 实际使用的 kernel SHA 正是 `51c40285…`，不会在启动时重新构建。
- 诊断命令设置 `STABILITY_DIAGNOSTIC_ONLY=1`、8 次重载、30 秒间隔、90 秒页面窗口和 60 秒保持目标。QEMU session 正常结束，driver 0、round 0、normalizer 0；正式 gate 按设计跳过（rc 78）。

## 与候选稳定性失败的关系

[最终候选稳定性 r1](345-T490-ac1032稳定性轮第八次重载页面无响应-20261119.md) 使用 kernel `ac1032fe…`，在正式 120 秒间隔下前 7 次通过、第 8 次无响应。此 baseline 控制使用 `51c40285…` 且 30 秒间隔，8/8 通过。后续在同一 30 秒 diagnostic-only 条件下，候选 `ac1032fe…` 也 8/8 通过，见 [report 348](348-T490-ac1032短间隔重载不复现nav08超时-20261119.md)。因此短间隔下重载次数本身不会触发该现象；目前的对照把待查范围收窄到正式 120 秒间隔下的长空闲/长运行行为，但根因仍未定。下一步对候选在 120 秒间隔、8 次请求下做 diagnostic-only 复现，再按候选内核 patch 逐项回退。
