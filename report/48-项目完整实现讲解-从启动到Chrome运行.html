0先把题拆开：这个项目在做什么

不要一上来就看代码。先把题目、评分和所处的位置坐标建立起来，后面每一步才知道为什么这样做。

0.1 一句话题目

题目本质

在组委会指定的 AArch64 QEMU 虚拟平台上，用指定的 Rust 内核 x-kernel， 把图形界面（Weston / Wayland）和浏览器（Chromium）跑起来， 正确渲染组委会指定的 HTML 页面，稳定运行不少于 10 分钟， 并提交内核兼容性缺口、修复补丁、可复现的测量方法与原始数据。

这是一道「移植 + 兼容性」题，不是写业务代码。你面对的不是空白项目， 而是一个已经能启动、但跑不动大型用户态软件的内核 —— 你的工作是找出并补齐它缺的能力。

0.4 三条关键认知

认知 01

不是「只能做内核态」

图形与浏览器合计 40 分落在用户态。但赛题原文要求「配置图形、输入、文件系统和网络所需的内核能力」—— 内核能力是图形分项的前置条件，两者不是二选一。

认知 02

内核态是分值最高、且无法绕开的单项

25 分只能自己啃，同时它是决赛「开源回馈 9 分」的唯一来源。上游 patch 的 review-merge 周期以周计， 第一周就要开始提。

认知 03

排查顺序必须是「先内核、后用户态」

遇到「图形起不来」，先读内核能力表（ioctl / syscall 分派表），再决定用户态怎么用。 反过来在用户态堆启动脚本、用排除法倒推内核，会浪费整轮整轮的时间。

0.5 全局总览

1项目从启动到运行的完整流程

整条链路拆成八个阶段。记住一个心法：每一阶段都有产物，下一阶段只消费上一阶段的产物。 任何一环断了，都会在后面以「现象」的形式暴露，而定位时应当回到产物那一环去查。

1.1 八个阶段的路线

  1. 环境准备 在 T490 上装齐 QEMU 10.2.1、Rust 1.95 与双 target、musl 交叉工具链、rust-objcopy。 可用的交叉编译工具链
  2. 平台参数定标 把赛题第七节(一)的全部取值收敛到单一真源，并做机器可校验断言。 platform-check.txt（35 项 PASS / FAIL）
  3. 内核构建 defconfig → 架构断言 → rootfs 扩容 → uapps → make build。这一步决定后面所有能力。 kernel.bin + SHA-256 指纹
  4. 镜像与 overlay 准备 准备基础镜像与运行时补包：eudev、seatd、libinput、SwiftShader。 agentos-weston.img + pkgs.tar.gz
  5. 单轮编排 换镜像 → 编译探针 → 注入 autorun / 页面 / autostart 钩子 → 回读逐字节自证。 注好内容的 disk.img + manifest.txt
  6. guest 内启动时序 udevd → seatd → Weston → Wayland socket → Chromium → 加载页面。 console.log · single-initial.log
  7. 采集与判据 QEMU monitor screendump 出 PPM，再与参考图做严格像素断言。 screenshots/*.ppm · ppm-summary.txt
  8. 性能测量 同配置重复不少于 5 次，取中位数并给出波动范围与宿主指纹。 raw.csv · summary.json
  9. 证据归档与提交 组装不可覆盖的证据包与索引，禁止覆盖旧轮次。 提交包索引

判据陷阱

-cpu cortex-a76 本身就是纯 TCG 的证据：xkmake 只在 accel.is_some() 时才填 host。所以判据是「命令行没有 -accel」， 而不是「命令行有 --no-accel」—— 后者是 xkmake 层参数，不会出现在 QEMU 命令行里。

1.4 单轮编排的八步

t490_round.sh 是宿主侧的「单轮引擎」，把「改一点东西测一轮」的重复劳动固化成流水线。 共 8 步，其中第 4a 步是踩过坑之后强制的。

  1. 前置预检工具预检、会话互斥（禁止 TCG 并发）、证据目录守卫。
  2. 换镜像把指定的基础镜像复制成本轮工作镜像 disk.img。
  3. 编译探针把 probe.c 交叉编译为静态 aarch64 可执行文件。
  4. 写 autorun 副本把 PAGE_URL 与 Ozone 运行期三元组烘焙进 guest 侧脚本。
  5. 注入并回读自证用 debugfs 注入页面整套与探针，再 dump 回来逐字节比对，不一致即中止。
  6. 注入 autostart 钩子写 /etc/profile.d/99-autostart.sh 并回读校验。缺它整轮静默空跑。
  7. 校验清单确认注入清单与 autostart 钩子真实存在。
  8. 起会话并取证纯 TCG 启动 QEMU；按间隔调用 monitor screendump；停机后回收完整 guest 日志。
为什么必须有第 4a 步

agentos 官方 kiosk 镜像的 /etc/profile.d/ 里没有 99-autostart.sh， 因此 /root/autorun.sh 永远不会被拉起 —— 整轮会「静默空跑」， 证据看起来正常但什么都没测。所以钩子必须随轮注入并回读自证。 换新镜像第一件事就是确认这个钩子。

2支撑 Chrome 启动所必需的内核组件

这一章回答「内核必须提供什么」。方法是先列需求，再映射到代码，最后看调用链。 不要一上来就翻代码 —— 先有了需求清单，翻代码才有目标。

2.1 Chrome 会向内核要什么

一个浏览器从零到画出第一帧，需要内核提供的十一项能力
Chrome 要做的事 需要的内核能力 缺了会怎样
进程创建与多线程 clone / clone3、execve、tid 与 tgid、set_tid_address 起不来，或线程组错乱
加载动态库与 JIT mmap / mprotect / mremap、memfd_create 崩在 ELF 加载阶段
进程间传递文件描述符 sendmsg / recvmsg 加 SCM_RIGHTS / SCM_CREDENTIALS / MSG_CMSG_CLOEXEC 子进程拿不到 fd，renderer 死
窗口与合成 AF_UNIX stream（Wayland socket）、wl_shm 共享内存 只有 socket，没有窗口
直接访问显示设备 /dev/dri/card0 加 DRM / KMS ioctl 全套 Weston 起不来
扫描输出 dumb buffer 创建与映射、附着 framebuffer、plane 提交 黑屏，报 Display output is not active
设备发现 /sys/class/drm、/sys/class/input、udev uevent 合成器根本走不到 open()
读取配置与状态 procfs 的 uptime / stat / loadavg / meminfo / statm，以及 sysfs 启动逻辑读到 0 值，行为异常
超时与等待 epoll / ppoll / poll、eventfd / timerfd、futex 卡死或忙等
沙箱 prctl(PR_SET_NO_NEW_PRIVS)、PR_SET_PDEATHSIG、seccomp 前置 子进程全灭
网络（NetworkService） socket / connect / TCP_KEEPIDLE 等 sockopt 报 ENOPROTOOPT，但不致命

2.5 sysfs 决定「设备是否存在」

图形链路能不能走通，第一关不是 open()，而是设备节点和 sysfs 存不存在。 Weston 14 的 DRM backend 会先用 libudev 去 /sys/class/drm/<name> 查设备：

查不到就直接返回，根本走不到 open() 与 libseat_open_device()。 所以无论怎么调参数、用不用 seatd，都必然失败。 本仓库的 fs/filesystems/sysfs/src/lib.rs 已经实现了这部分投射：

2.6 Chrome 到内核的调用链

3为使 Chrome 正常运行而额外补充的内容

上游内核能启动、能跑 shell，但跑不动大型用户态图形程序。 第 2 章是底座，这一章是我们在底座上补的砖，分四类。

3.1 四类补充总览

A

内核补丁

可直接写进缺口清单、可直接提上游。P0 至 P4 加后续若干项，落点集中在 io/drmdevice、net/knet、core/ksyscall、mm。

B

内核能力补齐

不是「改 bug」，而是「从无到有」：sysfs 设备模型投射、 /dev/dri/renderD128 别名、procfs 动态值。

C

镜像与用户态

基础镜像、运行时 overlay、autostart 钩子、官方三页套、单进程启动参数。 这些不是得分项，但没有它们就没有可测的对象。

D

测量与判据工具链

平台合规预检、像素判据、五次重复测量、host 侧 fallback 观测。 对应 15 分性能项与文档分。

3.6 最有价值的一课：两次已撤销的误修

这是整个项目最值得记住的教训，比任何一个补丁都重要。

两次误修的具体内容（均已回退）
误修 当时改成 真值 后果
A · 属性编号 0xAA 改成 0xA8，0xAC 改成 0xAA 0xAA 就是 GETPROPERTY，0xAC 就是 GETPROPBLOB，HEAD 原值才对 真实 libdrm 发 0xc04064aa，内核只认 0xc04064a8，返回 errno=95，读不到属性名，plane 类型越界被静默丢弃，最终表现为 Failed to find primary plane
D · GETPLANE 结构体 32 字节扩到 48 字节 标准 uapi 是 6 个 u32 加一个 u64，共 32 字节。crtc_x / crtc_y / x / y 属于 drm_mode_set_plane，不属于 drm_mode_get_plane 结构体大小编进 ioctl 号，编码从 0xC02064B6 变成 0xC03064B6，与标准客户端不匹配
机器证据

scripts/t490/abi_probe.c，宿主与 aarch64 双编译器复算。

由此确立的三条铁律
  1. io/drmdevice 的 uapi 必须做一次系统性核对：编号与结构体字段长度，双维度。
  2. 任何内核算术改动必须用真实 libdrm 或标准头文件验签，禁止用自写探针自证 —— 自写探针与内核共用同一个错误假设时，会「自洽变绿」，这是最危险的假阳性。
  3. 探针必须自带一个已知能通的对照，例如先跑 DRM_IOCTL_VERSION，证明探针自身编码正确。

4.3 血泪坑清单

改脚本之前先看这一节。

1 · autostart 钩子

agentos 镜像没有 99-autostart.sh，不注入就是整轮空跑。

2 · 不要用 pgrep 判存活

pgrep -x Xorg 在该 guest 恒为空，一律用 /proc/<pid>。

3 · socket 存在不等于服务可用

存在约 7 秒的「假可用窗口」，必须用功能门禁判断。

4 · 探针要自证

新探针先跑一个已知能通的对照，否则探针缺陷会被误读成内核缺陷。

5 · 改了编号必须验签

改内核编号或结构体后必须用真实 libdrm 验证，不能自证。

6 · /sys 运行时才能写

镜像里预置的 sysfs 内容会被 memfs 挂载覆盖。

7 · console 只有 tail 窗口

完整 guest 日志必须停机后用 debugfs dump 回收。

8 · guest 内 apk 极慢

依赖求解纯 CPU 且与宿主争抢，改用宿主侧跨架构预装或复用冻结镜像。

9 · 写镜像前必停 QEMU

改完必须执行 e2fsck -f -y disk.img。

10 · pkill 会自杀

pkill -f <pat> 会匹配承载它的 ssh shell，用字符类规避。

11 · 判「日志消失」要全局计数

必须全局 grep -c，不能看 tail 窗口。

12 · 新探针要进循环

新增 .c 必须同步加进 autorun 的探针循环，否则注入了却不执行。
