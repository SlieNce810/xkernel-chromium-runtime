## 修复 1：`MFD_ALLOW_SEALING` 单独启用

源码位置：`posix/mm/src/memfd.rs::MemfdFlags::allows_sealing`。候选实现用 `contains(ALLOW_SEALING | NOEXEC_SEAL)`，bitflags 要求两个 bit 同时存在，导致只有 `MFD_ALLOW_SEALING` 的合法 `memfd_create` 仍建立为不可 seal 文件；`F_ADD_SEALS` 返回 `EPERM`，写入和 grow/shrink 也没有按 seal 阻止。

修复改为 `ALLOW_SEALING || NOEXEC_SEAL` 任一标志即可启用 sealing，补丁为 [memfd-sealing-flags.patch](../patches/compat/memfd-sealing-flags.patch)。修复后 guest 12/12 通过，包括 F_ADD/GET_SEALS、sealed pwrite、grow/shrink、共享可写 mmap 拒绝、未开启 allow-sealing 时拒绝 seal、all-ones flags 返回 `EINVAL`，以及 `MFD_NOEXEC_SEAL` 自动设置 `F_SEAL_EXEC`。T490 原生 Linux 7.0 对照也为 12/12。

此前 Browser 的 7 次 `memfd_create` 错误 flags 为 `0xffffffff`；T490 原生 Linux 对同 flags 返回 `EINVAL`。因此这些行是无效 flags 负向检查，不是 `MFD_NOEXEC_SEAL` 功能调用失败。相关 path/flag 诊断证据见 [memfd flags diagnostic evidence](../evidence/2026-11-19_t490-codex-2026-11-19-memfd-flags-diagnostic-r1/)。

## 修复 2：`MADV_DONTNEED` 跨未映射 gap

Linux 原生控制（T490 7.0 与 WSL2 5.15）对覆盖 hole 的 `MADV_DONTNEED` 返回 `-1/ENOMEM`。候选原实现只遍历重叠 VMA，跳过 gap 并返回成功；原 C 探针也错误地把 `0` 写成 Linux 预期。

修复位于 `mm/memspace/src/aspace.rs::MmSpace::madvise_dontneed`：先检查 `[start, end)` 是否被连续 VMA 覆盖；存在 gap 时返回 `KError::NoMemory`，并在开始丢弃映射页之前退出。unit test 现在断言该 errno 且确认原映射仍存在；补丁见 [madvise-hole-ENOMEM.patch](../patches/compat/madvise-hole-ENOMEM.patch)。C probe 的期望已改为 Linux 控制 `ENOMEM`，T490 Linux、WSL2 与修复后 guest 均通过。
