# T490 procfs 分阶段计时与 Chromium 进程树采样诊断 R21（2026-11-20）

## 结论

R21 在 2 GiB AArch64 纯 TCG 上通过 Chromium 149 首页和一次真实重载的严格截图判据，随后完成 800 秒页面保持。首页首次通过时间为 589.187 秒，重载为 1/1；稳定性 driver 返回 PASS。该轮设为 diagnostic-only，正式 gate 按配置跳过并返回 78，因此它不是稳定性正式验收轮。

新增的 procfs 阶段计时数据定位到 resident-page 枚举：232 个完整计时样本中，该阶段中位数 212.308 ms、P95 1,599.454 ms；dense PFN mapcount 中位数 11.122 ms、P95 47.931 ms。resident-page 遍历是当前 procfs 快照的主要内核耗时，值得作为后续优化入口。

R21 的 900 秒 Chromium 进程树采样仍无效：232 个完整内存样本、1,436 行、208 missed、276 条采样错误，状态 `FAIL`；错误含 119 次 overrun、68 次 bulk endpoint unavailable、68 次 sample incomplete 和 21 次 process tree unavailable。该数据只用于定位，不计入四项正式性能指标，也没有可接受的 RSS/PSS/USS 峰值。

## 阶段耗时

以下统计对同一 sample ID 去重，每列 `n=232`，时间来自 guest `LINUX_CLOCK_MONOTONIC`，P95 使用 nearest-rank。内核 endpoint 分段来自完整样本；68 次 endpoint unavailable 不进入这些计时统计。

| 阶段 | 中位数 | P95 | 最大值 |
|---|---:|---:|---:|
| all-process resident-page walk | 212.308 ms | 1,599.454 ms | 6,991.286 ms |
| PFN mapcount pass | 11.122 ms | 47.931 ms | 170.767 ms |
| PSS/USS rollup | 3.691 ms | 13.743 ms | 46.351 ms |
| response formatting | 0.308 ms | 1.240 ms | 6.625 ms |
| kernel endpoint total | 234.570 ms | 1,665.746 ms | 7,066.663 ms |
| sampler procfs open/read/parse | 466.784 ms | 3,389.826 ms | 11,956.118 ms |
| sample work before CSV output | 1,366.751 ms | 7,341.505 ms | 19,693.535 ms |

`tree_snapshot_process_count` 是 PFN mapcount 输入中的全系统进程数，不等于 Chromium 树行数；`tree_snapshot_resident_pages` 是各进程的 resident user mapping 总数，会重复计算共享 frame。`sample_work_ns` 在 CSV 行写出和 flush 前取值；全周期 overrun 由独立错误日志统计。口径说明也保存在提取 JSON 中。

阶段时间显示 mapcount 不再是主要热点。下一项机制候选应检查 `resident_page_frames()` 的页表枚举和取页成本；另需把 endpoint read/parse 与内核总时长分开看，避免把用户态读取开销误归给内核。当前诊断不证明任何四项目标指标下降。

## 相邻轮次对照与限制

R20（相同 trace-off dense 基线、无分段计时）有 304 个 sample ID、151 missed、160 错误，overrun 中位数/P95/最大值为 2.130/17.361/27.152 秒，页面 ready 为 589.475 秒。R21 页面 ready 快 0.288 秒，但 sampler 的成功样本更少、missed 和错误更多；两轮都是诊断轮且 sampler 均失败，不能认定测量补丁带来收益或退化。完整前序对照见 [report 391](391-T490densePFN同条件Chromium内存采样重复对照R20-20261120.md)。

采集器变更兼容旧 10 列 CSV，并校验 19 列扩展记录的事件样本关联和计时值；抽取器回归分别为 7/7、8/8。R21 当前 C 源通过 AArch64 musl `-Wall -Wextra -Werror` 静态编译。由于 R21 实际 run 使用稍早的采样器源版本（哈希见 instrumentation 文件），新源码编译只作为工具检查，不混入 R21 运行二进制身份。

正式稳定性 30 分钟/10 次重载、四项性能指标的 before/after 各 5 次有效独立运行，以及 1.5 GB 资格线所需的有效进程树峰值内存仍未完成。R21 只增加了定位材料，不能替代这些验收项。
