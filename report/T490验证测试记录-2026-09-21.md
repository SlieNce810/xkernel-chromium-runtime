## 三、★ 核心发现：Weston 打不开 DRM 的三层兼容性缺口

### 缺口 1（最硬）：weston 14 强制 udev/sysfs —— 源码级证据
weston 14.0.2 `libweston/backend-drm/drm.c`：
```c
compositor->launcher = weston_launcher_connect(compositor, seat_id, true);  /* libseat */
if (compositor->launcher == NULL)
    weston_log("fatal: your system should either provide the logind D-Bus API, or use seatd.\n");

b->udev = udev_new();                                   /* 强制 udev 上下文 */
if (config->specific_device)
    drm_device = open_specific_drm_device(b, device, config->specific_device);
        └─ udev_device = udev_device_new_from_subsystem_sysname(b->udev, "drm", name);
           if (!udev_device) { weston_log("ERROR: could not open DRM device '%s'\n", name); }
else
    drm_device = find_primary_gpu(b, seat_id);          /* 同样走 udev 枚举 */
if (drm_device == NULL) weston_log("no drm device found\n");
```
- **实测现象完全吻合**：weston 报 `could not open DRM device '/dev/dri/card0'` 时
  **从未调用 `libseat_open_device`**（LD_PRELOAD shim 无该调用日志）→ 因为卡在 udev 查询
- **x-kernel 无 sysfs、无 udev、无 uevent** → libudev 无法工作
- 试验：手工伪造 `/sys/class/drm/card0/{dev,device/uevent,device/vendor}`（运行时创建可写）
  → guest 内可见 ✓ 但仍失败（libudev 需要完整 udev 语义，非单纯文件存在）

### 缺口 2：无虚拟终端（VT）→ seatd 拒绝代理打开设备
`seatd.log` 实测：
```
[INFO]  seatd/seat.c:48   Created VT-bound seat seat0
[ERROR] seatd/seat.c:215  Could not determine VT for client      ← 读客户端 tty 信息失败
[ERROR] seatd/client.c:176 Could not add client to target seat: Invalid argument
[ERROR] seatd/seat.c:544  Could not open VT for client           ← 拒绝服务
```
- 根因：seatd 绑定 VT 需要 `/dev/tty0`（x-kernel 无 4:0 驱动，mknod 后 open 得 ENXIO；
  符号链接到 `/dev/tty` 后错误变为 "Could not determine VT for client"，
  即 seatd 继续要通过 procfs 查客户端控制终端 → x-kernel procfs 支持不足）
- `drmprobe v2` 佐证：`stat /dev/dri/card0`/`open`/`ioctl(VERSION)` 全部成功
  → **设备本身没问题，是 seatd/libseat 的上层机制不满足**

### 缺口 3：libseat 备用后端缺失 + DRM ioctl 对 NULL 指针不兼容
```
[libseat/libseat.c:52] No backend matched name 'builtin'      ← Alpine 未编译 builtin 后端
drmGetVersion(fd=3) -> 0 errno=14 (Bad address)               ← EFAULT
drmGetDevices2(0, buf, 8) -> 0 errno=2 (ENOENT)               ← /sys/class/drm 不存在
```
- **`DRM_IOCTL_VERSION` 返回 EFAULT** 是可直接修的内核缺口：libdrm 的标准用法是
  **第一次传 `name=NULL/name_len=0` 拿长度**，x-kernel 对 NULL 指针做了 copy → EFAULT
- `drmGetVersion` 在 libdrm 里被广泛使用，此缺口影响所有 libdrm 客户端

### P0 ✅ 交付（commit `8162e8a`，tag `p0-drm-version-fix`）
- `DrmVersion::handle` / `DrmUnique::handle`：先填长度，`!is_null() && len>0` 时按 `min(len)` 写入（diff 32+/16-）
- **验收全过**：`drmGetVersion(fd) -> 0x40c2fb0 errno=0`（基线 NULL/errno=14），读到 `simpledrm 1.0`；panic=0
- 镜像冻结：`~/x-kernel/images/p0-drmversion-fixed.img`（sha256 `88f7152b…`）
- 注：pre-commit 的 fmt/clippy 需 pinned nightly-2026-03-08，本地用 hook 支持的
  `SKIP_FMT=1 SKIP_CLIPPY=1` 提交；**上游 PR 前需安装该 nightly 过全检**

### P1 路线修正与突破（v13–v16）
1. **x-kernel 已有 sysfs**：`memfs::SYSFS_TYPE`（ramfs）挂 `/sys` 且运行时可写 → **无需新 crate**，
   用户态伪造即可（`autorun fake_sysfs`）
2. **weston 起来的三件套**（v16 首次全通）：
   - `--drm-device=card0`（**必须用简写**——weston 将该值原样传给
     `udev_device_new_from_subsystem_sysname(udev,"drm",name)`，绝对路径会拼出非法 syspath）
   - `libseat-shim`（LD_PRELOAD 接管 libseat；enable_seat 必须延迟回调）
   - 伪造 `/sys/class/drm/card0/{uevent,dev}` + `/sys/dev/char/226:0/device/subsystem` 链接
3. **v16 结果**：`Output 'Virtual-1' enabled`，compositor capabilities 全表初始化，
   `desktop-shell.so` 加载并 launch 客户端 → **失败点推进到**：
   ```
   libwayland: file descriptor expected, object (10), message create_pool(nhi)
   Error: /usr/libexec/weston-desktop-shell apparently cannot run at all.
   Quitting...
   ```
   → **缺口 #4：unix socket SCM_RIGHTS 的 fd 跨进程传递失败**（wayland `wl_shm.create_pool`
   必须传 fd；客户端与 compositor 分属两个进程）。收尾修复方向：
   调试 `posix/net/src/cmsg.rs` 的 SCM_RIGHTS 收发（fd 在跨进程场景是否真正落地），
   或先确认 weston-desktop-shell 是否还缺运行库。
