# 基于 x-kernel 的 Chromium 运行环境构建与优化

## 方案与实现

宿主为 ThinkPad T490（Intel i7-8665U，14.7 GiB，Ubuntu 26.04.1），QEMU 10.2.1 纯 TCG 模拟 AArch64，guest 2 GiB / 4 vCPU。运行链为 virtio-gpu → DRM/KMS → Weston 14 pixman → Wayland/Ozone → Chromium 142，使用 SwiftShader 和 `--single-process --no-zygote --in-process-gpu`。这一路线完成官方本地 HTML、浏览器级 JS 交互和 CSS 布局验证。

基础镜像预装 Weston/Chromium；随包 p31 overlay 补充 eudev、seatd、libinput 与 SwiftShader。每轮复制基础镜像，通过 debugfs 注入启动钩子、完整三页和探针，读回校验后启动 QEMU。串口日志、宿主指纹、完整 QEMU 命令、guest 日志、monitor screendump 与像素判据共同构成可复核证据。

内核冻结为 `2a1b101ccf97ed255821b85628f366700089cda3`，主要修复涉及 DRM/设备发现、Unix socket fd/凭据传递、ppoll 分派、procfs、TCP 选项及 libc 错误码回退。交付实际源码及构建配置。源码归档中的 Git 历史可核对各提交，避免重复应用历史候选补丁。

## 验证结果

| 项目 | 结果与证据 |
|---|---|
| 主流程与稳定性 | T490 干净目录完整运行 900 秒；保持 615 秒，SINGLE_GATE=1；13 张 official-index 截图严格集全部通过，见 `evidence/t490-final/main/` |
| JS/浏览器交互 | T1–T6/F1、文本回显与计数的页面证据见 `interaction/`；输入属于 CDP/页面层，不能证明 virtio-input 全链 |
| CSS | `layout/` 保存最新滚动结论条 6/6；`layout/top-view/` 仅补一张已有首屏几何 5/5 原图及溯源，两者分别判定 |
| 性能 | 同一原始用户态栈五次观测：导航日志首次采样中位 75 s；首张通过的定时截图 180.2 s；宿主 QEMU 峰值 RSS 中位 1,695,736 kB（1,681,484–1,699,284）；单核尺度 CPU 中位 176.8%（173.017–178.520%），见 `performance/` |
| 演示 | `video/full-flow.mp4`，2026-10-14 实际新录 945 秒，1280×800 / 30 fps；对应录制轮浏览器保持 795 秒、SINGLE_GATE=1。主机录像为辅助演示，功能判定依据 QEMU 原始截图 |

75 s 为 15 秒采样发现导航日志的时间；180.2 s 为固定截图间隔下通过判据的观测时刻，均不等于精确首帧或页面加载耗时。RSS/CPU 是宿主 QEMU 观测，不能解释为 guest Chromium 独占资源。保持时长属于稳定性窗口。性能类别认定以实际评分规则为准。

首个可运行 tag `v0.1-first-runnable=f8b9224` 描述的是历史用户态条件；在当前未适配的用户态栈中因 PulseAudio mutex 断言及 crashpad 凭据问题不能完成页面加载。本提交仅提供当前原始运行栈五次绝对观测，不将“无法加载→可用”换算成性能改善百分比，不申请改善档位。

## 八条兼容性缺口与覆盖边界

Linux 对照为同一 T490 的 native x86_64/glibc 和 AArch64 静态 musl 经 qemu-user；后者调用宿主 Linux 内核。Guest 和 Linux 原始输出在 `evidence/t490-final/compatibility/`。

| 缺口 | 探针及当前结果 | 尚未证明的范围 |
|---|---|---|
| G1 fd 下界与继承 | submission_gap_probe：F_DUPFD≥100、fd3 fork/exec PASS | Chromium 完整 zygote/sandbox 协议 |
| G2 Unix ancillary/凭据/半关闭 | fdprobe、sandboxipcprobe、seqpacketprobe、compatprobe：专项 PASS | 完整 renderer 多进程生命周期 |
| G3 ppoll/time64 | libc 原生 ppoll PASS；raw 414 扩展单列 | 信号掩码、超时精度、全部 ABI；414 非 Linux AArch64 原生 ppoll |
| G4 procfs | uptime 从 1.867 增至 2.070，其他字段按原始输出观察 | 完整线程/内存记账；guest VmRSS 不作为有效 RSS |
| G5 PDEATHSIG | set 返回 0，但 get 读回 0，未保持 SIGTERM，FAIL | 父死亡投递、fork/exec、subreaper 等语义 |
| G6 TCP keepalive | IDLE/INTVL/CNT set/get PASS | 实际报文、超时与调度 |
| G7 PI futex/NOFILE | PI 返回 EOPNOTSUPP；NOFILE 1024；提升 65536 返回 EINVAL | Linux PI 语义及 65536 fd 容量 |
| G8 virtio-input | evprobe 仅枚举节点/能力 | QMP→evdev read/poll→页面回显的真实键鼠链 |

没有单个探针覆盖全部八条。compatprobe 的 madvise 空洞检查在 guest 返回 0，与 native Linux ENOMEM 的差异保留。renderer 子进程、多窗口、多页面及硬件输入链不在已通过范围。
